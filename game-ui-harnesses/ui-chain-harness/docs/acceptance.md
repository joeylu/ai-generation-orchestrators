# 当前链路验收指南

本指南把“实现存在”“离线回归通过”“真实调用完成”“外观与需求接受”分开记录。当前可以从空组件库起步，贯通可选 S05 材质、16 类组件、AI 面板、画布编辑副本；本指南不预填任何真实生成质量结论。

## 验收前

按[本地 Studio](local-studio.md#启动)安装锁定依赖、构建模板和合同、启动回环服务。使用独立测试项目名称，记录本次项目、批次、面板和版本标识。空库没有可用组件时面板生成按钮禁用，这是正常前置限制。

核对当前适配器环境是否可用；网页预检只检查当前环境，不保证远端成功。已存在运行任务时先检查其状态，避免重启打断调用。本地报告、原始输出和生成清单由程序产生，不手改成功状态。

真实生成须在网页查看本次范围和不可变计划后确认。图集批次和面板调用分别确认；补图、澄清后下一版计划也分别确认。离线测试、恢复接收和确定性后处理不需要也不包含新的模型生成。

## 逐节点检查

| 节点 | 输入 | 程序输出 | 人工验收点 |
| --- | --- | --- | --- |
| 项目与风格 | 名称、参考 PNG/JPEG、补充描述、材质开关 | 校验过的项目草稿、参考摘要、style、冻结批次 | 显示图与期望风格一致；旧导入草稿没有隐式增加材质调用 |
| S01–S04 与可选 S05 计划 | 同一参考和风格、组件/材质模板 | 每图独立计划及共同批次摘要 | 模板修订3开启材质为4+1张、32+3件；关闭为4张、32件；旧修订2为30基础件；仍为16类组件 |
| 批次执行 | 当前摘要的一次确认 | 每图最多一次调用记录、原始 PNG、接收/失败回执 | 每张图真实状态和耗时可见；失败与未知不伪装接收成功 |
| 组件定位和切线 | S01–S04 原图与冻结来源 | 归属、实际裁切、九宫格、安全区和处理证据 | 主体齐全、无串件；不同尺寸下边框和高光没有明显拉坏 |
| 材质提取绑定 | S05 语义槽位、raw 摘要、基础皮肤 | 3 份材质 PNG、必要的透明 RGB 派生源、轮廓裁切/重放报告、`materialAssets` 和 `surfaceStyles` | 标题/分组在唯一无冲突且提案不重叠时保留跨 body 的完整轮廓；面板仍取固定内部样本；核对字色、接缝和原始来源 |
| 组包与组件消费 | 部件、材质、元数据、合同 | 验证后的皮肤/消费包、16 类组件画布、报告和摘要 | 试玩各类控件；宽窄尺寸、选中态、滚动、弹窗和字色符合预期 |
| AI 面板计划 | 需求、组件版本、预设/自定义、比例 | 冻结 session、Schema、consumer、合同快照 | 选中皮肤/方向正确；自定义或仓库范围符合当前能力 |
| 面板模型与转换 | 当前面板计划一次确认 | 原始响应、回执、`COMPILED` / `NEEDS_INPUT` / `REJECTED` | 需求中的文案、数值、顺序、状态和动作保真；不支持内容有明确原因 |
| 面板预览与交付 | 已编译内容和对应真实皮肤 | 所选方向预览、PanelDocument、ZIP/原生报告 | 无截断、越界、遮挡或异常滚动；下载与当前原始版本对应 |
| 编辑与保存副本 | 核验的原始版本、合法编辑操作 | 独立修订及编辑 JSON | 返回预览/刷新能读保存结果；切换“原始生成”仍见原样，原始交付未变 |

若只验收其中一段，明确写出起止节点，不把替身运行当成真实模型调用。素材来自本地导入时标注来源；不能把手配素材描述成 S05 自动生成验收。

## 推荐真实验收顺序

1. 从空库新建一个参考图项目，保持材质选项开启。先查看五图确认范围；取消一次，确认没有模型提交。重新进入当前项目后，再由用户确认本批。
2. 等待逐图返回，核对 5 张卡片及接收数量。保留失败或原始检查偏差，不用补图掩盖已有可恢复输出。
3. 收齐后等待本地流程完成。在组件画布核对标题、分组底边与装饰是否完整，面板平铺是否混入透明带，以及 16 类组件的关键交互与尺寸变化。若报告有派生源，核对 raw 摘要保留、仅 alpha=0 像素 RGB 归零、可见 RGB 与所有 alpha 变更数均为 0，并可从 raw 重放。记录外观是否接受，不能仅依据检查报告下结论。
4. 选择这套组件生成一个预设或受限自定义面板，固定横竖比例，核对确认里的组件版本，再确认一次调用。若返回澄清，按原任务回答并对新计划单独确认。
5. 查看面板实际内容和交互，下载原始交付。另改一处文字或尺寸、保存副本；返回预览并刷新，核对保存版与“原始生成”互不混用。
6. 如需验收仓库，使用专用“仓库面板”入口，给出明确物品与数量并选择行列。核对 AI 的名称、数量、格位、选中项和空位；无图集时应显示名称，不编造图标。仓库采用 context 0.12 / intent 0.13，不能以普通自定义结果替代这条分支。

关闭材质的四图路径、旧四图草稿导入、单图恢复和补图只在相应场景需要时验收；不要为了覆盖故障而故意消耗真实模型。失败分支优先用离线夹具验证。

## 失败与恢复

| 现象 | 核对与下一步 | 模型调用边界 |
| --- | --- | --- |
| 预检失败 | 查看当前检查标识，修复运行服务的环境后重新预检；保留未提交计划 | 预检本身不调用模型 |
| 运行很久 | 对照项目/批次/面板 ID、逐图状态、原生回执和时间；确认是否只是页面旧状态或同名旧任务 | 未知结果不重复提交 |
| 已结束但缺图 | 先点“检查并恢复已返回图片（不生成）”，核对同计划原图与工具证据 | 恢复零生成；不能替换已接收图 |
| 无可恢复的缺失图 | “仅补生成 Sxx”准备新计划，查看范围并重新确认，只补这一张 | 新的单次调用；其余图及失败记录保留 |
| 拆分、切线或 S05 来源/主体检查失败 | 查看实际原因，保留原图和候选；S05 全画布不透明、空槽、纵横比或源摘要不符仍停止。仅 alpha=0 的非零 RGB 可生成独立规范化源；槽外残留、同纵横比分辨率偏差和平铺接缝可能仅告警，仍须视觉复核 | 不自动重新生成或弱化来源/摘要要求 |
| 暂时性本地错误 | 按[本地恢复策略](local-recovery.md)有界继续；工具变化时复用原图准备新的确定性任务 | 不提交模型 |
| 面板要求补充需求 | 在同一任务保存回答，检查下一版计划后重新确认 | 每个新计划一次，旧结果保留 |
| 面板转换拒绝或调用中断 | 查看原始回执、转换标识及支持范围；修复后需要新的明确决策 | 同一已提交计划禁止自动重投 |
| 交付显示找不到或仍在计时 | 先核对后台记录和实际 ID，再刷新对应项目/作品库；不得手写完成状态 | 不因页面问题重生成 |
| 副本保存冲突或读取错误 | 保留当前草稿，重新读取对应版本；支持切回原始预览时明确使用原始版 | 不修改原始交付，不调用模型 |

不要删除 attempt、授权、回执或交付清单来“解锁”；不要把旧失败改成成功。修复流程后应能解释原始来源、当前版本和新旧调用的关系。

## 离线回归

在本 Harness 目录运行：

```sh
npm test
node --test tests/skin-material-generation.test.mjs tests/material-atlas.test.mjs tests/material-atlas-input.test.mjs tests/skin-batch-cli.test.mjs tests/studio-component-batch.test.mjs
npm run components:check -- --browser chrome
npm run editor:check -- --browser chrome
node scripts/studio-check.mjs 4321
```

测试必须使用夹具或替身，不连接真实模型、私有生成服务或 GPU 生成。`studio-check.mjs` 未指定配置时自动创建 `work/studio-fixtures/<UUID>/`：合成 PNG、随包字体、正常皮肤导入、消费包和设置预览均由程序构建，再启动隔离回环夹具。它不读取真实 `work/studio/project.json` 或历史成功记录；报告写在新夹具目录中的 `ux-browser-check.json`，命令打印确切路径。浏览器检查使用已安装 Edge，与正式 Studio 使用不同端口，所有模型操作是内存替身。

需要复用同一套夹具时，可先运行 `node scripts/studio-fixture-build.mjs --out work/studio-ux-fixture-local`，再运行 `node scripts/studio-check.mjs 4321 --fixture-config work/studio-ux-fixture-local/fixture.json`。构建目录须为新目录，程序不覆盖原输出。显式配置必须声明离线合成来源，不能误把真实 Studio 配置传作夹具。单独查看夹具可用 `node scripts/studio-ux-fixture.mjs 4322 --fixture-config work/studio-ux-fixture-local/fixture.json`。

浏览器检查保留位置参数 `[端口] [截图文件] [消费包目录]`；消费包用于离线运行时更新候选校验，须为可校验的 work 相对目录。附加 `--fixture-config` 不改变位置参数含义。缺省截图保存在系统临时目录；截图与夹具报告不是生产交付。检查覆盖默认五图、关闭材质时四图范围、缺失面板路由以及恢复/重启交互，运行后阅读实际报告，不预填通过次数。

`studio-real-acceptance.mjs` 和 `studio-real-followthrough.mjs` 已退役，不作为当前生成或继续生成入口。真实验收通过网页逐次确认并记录实际结果；旧脚本输出和历史记录只作为相应时期的证据。

## 记录结论

至少记录：版本/配置摘要、项目与批次标识、图集数量、是否含 S05、真实调用次数/是否发生补图、确定性步骤结果、面板标识和所选方向、语义与外观检查结论、原始与副本隔离结果、未覆盖项。原始回执中的 `productionReady: false` 和 `visualAcceptance: unreviewed` 不能由文档或 Agent 改成已接受。

当前入口状态说明实现边界，实际测试数量及真实验收结果由本次程序证据和人工检查产生；[执行记录](execution-plan.md)中的旧端口、旧资产和旧统计不继承为新一次验收结果。
