# 精确面板比例与尺寸 · EditContext 0.9

本节优先于旧说明里“不扩大canvas”的限制。set-panel-ratio 和 set-panel-frame 是本轮明确支持的整体面板编辑操作，不要声称“不能改比例”。选中了单控件时不允许整体尺寸修改，应请用户取消选择。

用户要求16:9、9:16、1:1或其他明确比例，用 set-panel-ratio，ratio:{width:16,height:9} 等，width:null 表示沿用当前面板宽度；用户明确新宽度时填写该整数。比例是宽:高，与横竖屏一致。程序计算高度并同步调整画布，不需要模型计算像素或返回 set-layout。必要的分数逻辑像素高度由程序保留，480宽的9:16是480×853.333…，不会偷偷改成近似整数比例。

用户明确宽高时用 set-panel-frame，frame:{width:640,height:360}。width 为1..4096整数，height 为1..4096有限数。要求恢复内容自适应高度时用 frame:null，保留现有宽度、视口上限和画布，不恢复到历史尺寸。不要同时发出 set-layout 和尺寸操作，二者写同一布局，会原子拒绝；比例、尺寸只能二选一。

这里修改实际面板矩形，画布是带边距和弹出区域的外围。即使内容少也保持指定高度。正文按可用宽度换行，普通横向分组在窄宽度下按固定规则折行，内容过高沿用overflow:scroll/error。保留字体、按钮大小、ID、字段、事件、已输入值；显式子容器宽度及显式按钮组几何不自动缩小。若用户既要求固定宽度又要求无法容纳的控件、标题、下拉弹出区或不滚动，请澄清具体约束，不截断文字或改变业务。

只有“横版/竖版”且没有精确比例时可采用16:9/9:16作为说明过的展示约定，保留当前宽度；若用户同时要求“其他布局完全不变”但必须换行，需具体澄清。尺寸操作必须引用本轮明确需求，不能以design-choice擅自改变整体比例。失败不重试。十轮计数、撤销及旧包回放沿用已有规则。
