# Studio 真实用户输入测试清单

这份清单固定 40 个待测场景：10 个生成、12 个修改、8 个澄清、10 个操作与输入边界。
它是测试设计，不是通过报告。创建清单没有调用模型；逐项执行状态见
[2026-10-06 验收记录](user-input-acceptance-2026-10-06.md)：累计 40/40 通过。
C01、C02 修复后按用户新批准的三次真实调用完成复验，原失败保留。固定样本通过不代表所有输入都稳定。
以前的 16 面板评测不能替代这些语言改写、交互过程和编辑依赖的验证。
新增的[72个需求探索场景与能力缺口](user-edit-exploration-matrix.md)独立记录为待测，不计入本清单已通过的40例。

## 怎么判断通过

- **生成 / 修改成功**：实际点击 Studio 按钮，模型方案通过协议，实际预览与独立业务预期一致，交互及导出保留这些语义。
- **澄清成功**：显示针对本请求的具体问题，不伪造缺失业务值，不替换原面板，不先应用部分修改。补充回答后由用户再次点击。
- **输入或操作保护成功**：无效操作不调用模型，忙时不重复提交，取消或失败不改原面板和试玩值，过期结果不覆盖新状态。

不要把“协议通过”直接算作“需求通过”。标签、顺序、默认值、当前值、提交 / 重置范围都要独立检查。
模型生成、模型编辑、确定性编译、浏览器交互分别记录结果；夹具或导入不能代替按钮的真实调用。
每次点击只调用一次模型，失败不自动重试。连续编辑需要明确记录每个步骤的独立调用；不是整条链只调用一次。
成功和失败都保留，记录请求原文、来源面板摘要、调用回执、模型方案、具体错误字段、截图和浏览器检查。

## 三份起始面板

修改案例默认先打开对应基准，每个独立案例从相同基准开始，避免上一个案例的结果污染本例。
不要求重复生成基准；可复用真实生成并验证过的 PanelBundle。

**S：声音基准**

> 生成“声音设置”面板。依次放主音量滑条、音乐音量滑条、静音开关和“恢复默认”按钮。两根滑条范围都是0到100、步长1，初值分别70和30。静音默认关闭，打开表示静音。所有控件可用。恢复默认只重置主音量、音乐音量和静音。不要添加其他控件。

**F：角色基准**

> 生成“创建角色”面板。角色名输入框，单行文本，初始为空，占位文字“请输入角色名”，必填，最少2个字符，最多12个字符。确认按钮校验并提交角色名；取消按钮只通知宿主，保留输入。所有控件可用，不添加其他内容。

**T：页签基准**

> 生成“游戏设置”面板，包含“声音”和“显示”两个横向页签，默认打开声音页。声音页依次放主音量滑条，0到100、步长1、默认70；静音开关，默认关闭，打开表示静音；恢复声音按钮，只重置声音页这两项。显示页依次放亮度滑条，0到100、步长1、默认60；全屏开关，默认开启；恢复显示按钮，只重置显示页这两项。全部控件可用，不添加其他内容。

输入限制当前按 UTF-16 单元计数，通常一个 emoji 占两单元；测试要把“用户认为的字符数”和协议长度区分开。
进度是宿主更新的只读展示，不会自行加载；按钮通知也不等于真的连接游戏业务。

## 操作和边界：模拟真实使用过程

这些案例用实际操作，不是只看模型输出。没有有效点击就不应产生模型调用；取消后的再次点击属于用户新请求。

| ID | 操作 | 独立验收点 |
| --- | --- | --- |
| U01 | 需求描述和修改要求分别只填空格、换行、Tab，再尝试点击。尚未打开面板时也试修改按钮。 | 本地提示或按钮不可用；模型调用为0；现有面板不变。 |

| U03 | 在一条有效需求上快速双击生成；编辑时也快速双击，并尝试在忙时点击另一种提交按钮。 | 单次操作至多一次真实调用，忙时互斥；不创建重复面板或重复编辑历史。 |

## 建议第一批顺序

先跑 G02、G05、G08、E01、E02、E03、E05、E10、C01、C04、C07、U06。
这12个场景覆盖口语、进度、Unicode、保留试玩值、新增字段、联动重置、删除依赖、连续编辑、补充回答、越界、未实现能力和长度冲突。

第二批补其余语言和状态用例；第三批专门测双击、取消、长文本、多窗口以及导出往返。
同义改写还应使用不同真实请求分别测量。重复成功可以记录稳定性，但不能覆盖早前失败或推断所有用户输入都能通过。
