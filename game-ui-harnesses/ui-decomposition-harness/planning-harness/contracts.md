# 两个核心合同（精简设计 0.5）

这是拟议合同，未实现独立运行入口。机器 schema 目前只覆盖视觉计划；
冻结输出沿用原程序格式，交接包装待实现。辅助记录不等于独立业务计划。

## 调用输入：参考图、目标、执行配置

- **参考图**：原始图片；宿主保存指纹、尺寸及实际送给模型的观察图。
  首版只接受未缩放、未裁剪、无需 EXIF 旋转的恒等坐标映射；其他情况先阻断，
  后续再实现显式转换适配。禁止模型看到旋转后的图却用原图坐标冻结。
- **拆分目标**：当前固定默认 `editability:static-composite`，
  `independentTargets:string[]` 默认 `[]`。宿主直接采用固定原则，只将用户明确要求
  单独编辑的对象填入 independentTargets；没有这类要求就保持空数组，不让模型
  另做一轮目标规划，也不根据图片中出现按钮或图标自行切换模式。
  independentTargets 是额外指定要求，不是默认拆分的前提；空数组仍按重要视觉单元拆分。
  局部独立编辑要求不自动升级为全局独立素材模式。
  场景和固定面板装饰尽量整体保留，重要对象保留观察及归属，普通文字排除，
  美术字作为素材，没有隐藏状态扩展。static-composite 不等于将整张 UI 扁平化为一层。
  `independent-assets` 仅作为未来保留项，尚未验证，不是当前已支持或自动可选的模式。
- **执行配置**：程序使用的尺寸上限、质量策略、调用上限和编译策略版本。
  不进入 LLM 视觉合同。敏感 provider 配置留在后续执行器，公共产物不含凭据或主机路径。
- **固定文字策略**：宿主使用 `remove_ordinary_text_preserve_graphic_symbols`，
  由编译器写入素材生成提示词。普通文字排除、图形符号保留；无需模型回传策略、
  逐条文字区域或 OCR 结果。该策略不是精确擦除遮罩，也不是去字成功证明。

默认输入由宿主提供，不要求用户填写 JSON，也不要求 LLM 回传：

```json
{"editability":"static-composite","independentTargets":[]}
```

例如用户明确说“购买按钮要单独换皮”，只将“购买按钮”加入 independentTargets，
其余部分继续遵循固定原则。若用户明确要求全局 independent-assets，需另行确定并
验证其合同与行为，不能把现有默认实现宣称为已覆盖该模式。

## 合同 A：视觉计划 JSON

生产方：M1 的 LLM，或 M2 的复核者修订。消费者：M2/M3。
草稿和复核后版本使用**同一个 schema**，不在模型 JSON 中设置审核通过标志。

| 字段 | 内容 | 作者/用途 |
|---|---|---|
| `kind` | `ui_visual_plan_v5` | 固定合同标识；素材显式区域；对象框可为 null；历史版本不自动转换 |
| `coordinateSpace` | `reference-normalized-ltrb` | 归一化半开区间边界 |
| `materials[]` | `id,label,role,zOrder,bboxNorm` | 最终素材候选及回拼顺序，role 为 background/foreground |
| `objects[]` | `id,label,kind,bboxNorm,materialId` | 原图观察、视觉分类和素材归属；bboxNorm 默认 null，仅作辅助定位 |
| `unknowns[]` | 简短问题字符串 | 需要 M2 解决或明确处置的问题 |

[完整 Schema](schemas/visual-plan.schema.json)。

### 对象分类 kind

`objects[].kind` 是必填的视觉分类；顶层 `kind` 仍是合同版本标识，两者不同。

| 值 | 含义 |
|---|---|
| `background` | 全画布场景背景 |
| `panel` | 面板、对话框、大型底板/边框 |
| `card` | 重复卡片、槽位或行表面 |
| `button` | 可见按钮整体或按钮底板 |
| `icon` | 独立符号、功能图标或货币图形 |
| `illustration` | 商品插画、肖像、带框图片等完整图像 |
| `badge` | 徽章、缎带、状态标记 |
| `decoration` | 固定角饰、连接装饰等 |
| `logo` | 造型构成身份的 Logo、字标或美术字 |
| `unknown` | 不能可靠分类；须在 unknowns 中注明对象 ID 和疑问 |

分类描述外观，不推断运行时组件、交互能力或生成路线。同类对象仍独立观察，
不自动复用或合并。不同 kind 可归同一素材，例如 panel 和 decoration 共属面板素材。
`materials[].role` 仍只区分背景/前景，不新增对象级 role。
当前不新增 parentId；素材归属不代表视觉父级或遮挡树，未来如需子元素移除再定义。
本设计尚未发布运行 API；早期缺少对象 kind 的设计示例需重新分类，不能按名称猜测补齐。

### 分组规则

- 多个 objects 指向同一 materialId，表示它们要**共同保留在一张素材中**。
- 分组不是像素复用：两枚金币若需要各自独立编辑，应有各自 materialId；
  首版不提供 canonical/reuse 字段，不以形状相似自动合并实例。
- 一个素材对应一个最终独立图层，不能用生图次数倒推拆分粒度。独立 ui-layer-harness
  的可选 sheets 模式通过冻结的生成分组计划将多份素材放进一张素材板，再逐份提取；
  板内分组不改变 materialId、状态归属或最终位置。原 single 模式仍是一素材一请求。
  该扩展不代表原正式链路支持素材板，见相邻 ui-layer-harness/docs/GENERATION-SHEETS.md。
- 非普通文字内容应在 objects 中有归属。普通文字由统一策略排除，不列入 objects，
  也不要求 textRegions。美术字在 objects 中作为图形描述。
- 整幅背景必须是一个 background 素材且有一条全画布观察；其余对象可覆盖该区域。
  覆盖检查不能把全画布背景当成“所有子物体均已检查”的证明。
- 拟同一素材内的装饰若与其他素材相互穿插、无法通过一次绘制正确回拼，M2 要拆开。
  zOrder 是素材级，不描述已合并素材内部的运行时父子关系。

### M1 判断规则与 M2 复核重点

- static-composite 表示交付当前画面可回拼的素材，不允许跨独立控件或可见状态边界扁平化。
  不同按钮/标签分别导出；固定功能图形随各自按钮保留，不因相邻、同色或共同布局而合并。
  单个按钮附带的名称铭牌或文字底座属于该按钮外观；“独立标签”仅指有自身控件/状态边界的标签。
  用户明确指定单个复合控件整体交付时，仅该组可合为静态素材；内部图标和按钮仍以 objects 记录，不扩展合并到相邻控件。
- 重复列表区分可替换内容、行/槽底板及状态表现。技能/物品槽图标具有独立内容身份时
  逐实例导出，固定画框随图标；固定构图中的物品插画仍可随其卡片，肖像与固定框整体保留。
  行底纹若只是母板的固定纹样、没有独立控件或状态边界，可与母板同素材；仍逐行记录对象，保留独立内容和状态归属。
  判断依据是边界、重复结构、内容及状态差异，不能仅按 icon/illustration 分类决定。
- M1 必须观察可见选中/未选中、勾选/未勾选、启用/禁用差异，在现有 label 中记录当前
  状态及图像依据；M2 检查状态是否误作固定装饰、与可替换内容烘焙，或不同控件错误合并。
  状态表面与内容分离，独立勾选标记单独导出。融合效果允许完整选中表面，不强行推导
  透明差分，不叠加重复完整底板。仅回拼原图实际出现的实例和状态，不生成未见变体。
- 滚动条按可见证据拆分轨道与滑块；固定端饰随轨道，独立端部控件另行判断。
  位置不等于选中状态；不推测隐藏的悬停/按下外观，状态或边界不明进入 unknowns。
- M1 对可见进度条记录填充方向及粗略程度（空、部分、接近满格）；M2 对照条内像素核对。
  邻近数值可辅助解释，不得替代视觉证据；笼统的“绿色填充”不足以区分不同当前状态。
- 固定读数卡默认整卡交付。若已有受审查的整卡生图比例或轮廓失败证据，新规划可把可伸缩空框与刚性图标、当前进度组分别作为素材，仍按同一静态卡片回拼；M2 核对唯一归属、相对位置与遮挡，并仅允许空框满足条件时使用框体适配。没有证据不因预想的生成困难过拆，也不把不透明截图直接当透明底框素材。
- 固定面板与装饰仍可合并，完整容器外框不因子元素独立而缩小。
  固定徽饰或吊饰即使突出、覆盖其母板，只要与母板可作为一张图层回拼，仍归母板；覆盖母板本身不是穿插依据。
  只有不跨独立控件、可替换内容及状态边界的固定装饰组才可合并。
  本版不新增状态机、变体或复用字段；label 是语义观察，不能宣称运行时可切换状态 API 已实现。
- 不自动拆分场景内对象或一幅插画内部的人物/道具，不推测不可确认的隐藏对象。
- 普通文字与美术字按渲染方式区分，不以粗体、描边或识别置信度作为分界。
  视觉身份依赖不规则造型、多色填充、定制轮廓或融合图案时才作为图像保留。
  普通文字不进入 objects；拿不准某处是否属于美术字时记录 unknowns，不要求逐条文字定位。
- 重复实例逐个观察位置和边界，不机械复制框；这不授予像素复用资格。
- 阴影、光晕、分隔线默认归入所属素材，不能因未独立列出而丢失；真实空隙保持空隙。
- 父表面与子对象分别描述自身负责的内容，避免重复描述整个组合。区域重叠本身合法，
  全画布背景仍显式存在；要消除的是重复语义，不是把所有框强制切成互不重叠。

这些规则使用现有字段表达，不新增父级、分割提示点、修补模式或 OCR 输入约定。
它们是视觉判断要求，JSON Schema 通过不能证明已经遵守。

### M2/M3 必做的关系检查（超出 JSON Schema）

- 各数组 ID 唯一；每条 materialId 必须存在，每份素材至少对应一条对象观察。
- 恰好一个背景，背景严格低于所有前景；前景 zOrder 可重复，数组顺序不承担层级语义。
- 同层不同素材按声明的素材框逐对检查正面积相交；边界相接不算相交。
  存在相交时输出 SAME_LAYER_OVERLAP_REVIEW 并定位素材对，阻断绘制编号派生，交给 M2。
  这是保守的区域检查，框内空隙可能误报，不证明 Alpha 遮挡；不能靠省略或缩小辅助框绕过。
- 无上述冲突且引用/几何等关系检查通过后，程序按 (zOrder, 素材 ID 的 ASCII 字典序)
  稳定排序，派生从 0 开始的唯一 drawIndex，保留模型原始 zOrder 和源计划摘要。
  drawIndex 不进入模型合同，不因 JSON 数组重排而变化，也不表达新的视觉判断。
- M2 发现真实遮挡时修订相关素材 zOrder；若是框过大导致的假相交，只在有图像证据时
  修正框。透明孔洞导致无法仅靠框消除歧义时保留阻断，当前没有自动豁免或人工勾选旁路。
  不同层之间仍须由 M2 检查真实顺序，程序不能从数字本身证明视觉正确。
- 恰好一个 kind=background 的全画布对象，且它引用 background 素材；其他对象
  可归背景素材以记录固定场景细节，但不能据此把它们的 kind 自动改成 background。
- kind=unknown 时必须有指向该对象的疑问说明；M2 明确分类或记录允许保留未知的范围。
- 素材框及非 null 的辅助对象框满足 `0≤left<right≤1` 与 `0≤top<bottom≤1`；拒绝非有限数。
- 未知项在复核记录中逐条解决或明确可接受范围，阻断项不能被静默清空。
- 素材 bboxNorm 是候选裁片区域的唯一来源，必须覆盖要保留的突出装饰、边框等内容。
  它是归属轮廓的轴对齐包围区域，不是像素掩膜；不规则轮廓周围的必要空隙不构成缩框理由。
  过大/截断的视觉问题须指明边及可见极值依据，不能用缩框掩盖归属疑问。
  背景素材框必须为 [0,0,1,1]。对象辅助框默认 null；提供时必须位于所属素材框内，
  越界报告 OBJECT_OUTSIDE_MATERIAL，不自动扩张素材区域。M2 依据原图决定改素材框、辅助框或归属。
  素材框不证明间隙、透明度和被遮挡部分正确。

坐标转换由程序完成：`[floor(lW),floor(tH),ceil(rW),ceil(bH)]`，使用明确的数值
解析与舍入规则。结果仍是模型估计区域，不得标为精确 Alpha 测量。
中心点与输出尺寸由素材像素框派生，不要求模型重复输出；不得用辅助对象框重算素材区域。
objects[].bboxNorm 键必填但值可为 null，以兼容 CLI 结构化输出。
模型不填写哈希、命令、预算、输出模式、可见留白或生成授权。

## M2 的辅助复核记录

M2 默认只做问题检查，不默认重写全量 JSON。关注重要素材漏件、错误合并/拆分、
明显裁切边界和遮挡次序；不检查逐条文字区域，也不重新推导全部素材。
问题清单使用下文的问题字段，由程序绑定源计划摘要；无问题时原计划字节不变。
有问题时只替换相关对象/素材记录或明确增删必要记录，并检查受影响的引用与层级。
保存结果仍是完整的同一 schema 计划，但不要求模型重新输出所有未变记录。
局部编辑必须绑定源摘要，过期修订拒绝；合并程序、补丁传输格式尚未实现，不能宣称可调用。
修订后重跑结构检查并复核受影响区域；有阻断问题则停留在 M2，不无限循环。

程序保存：原图/目标/计划的 SHA-256、复核者类别、覆盖/分组/几何检查结果、
未知项处置、实际时间及证据引用。状态为 pending/reviewed/blocked。
记录不重新定义素材列表或归属；业务修改只发生在视觉计划的新版本中。

旧 v2 适配所需的测量或粒度证据可作为具名辅助证据引用，并绑定当前计划；
它们不能覆盖视觉计划的语义。没有这些证据时，M3 必须返回阻断问题。
结构校验通过不等于规划复核，也不等于 human_visual_acceptance。

## 合同 B：冻结执行计划

生产方：M3 的确定性程序。消费者：现有生成执行链路。

这里的“合同”是一份可验证的冻结产物集合，不要求把所有文件塞进一个 JSON。
核心继续是现有 `batch.json` 和它引用的 plan、输入参考图、逐请求裁片、prompt/request。

| 必须表达的内容 | 现有来源 |
|---|---|
| 计划身份与冻结摘要 | plan digest、batch digest |
| 输入身份 | 参考图/裁片 SHA-256 |
| 素材、位置、尺寸与输出模式 | plan.json |
| 确切生成提示词和输入 | 每个 request.json、prompt.txt、crop.png |
| 请求清单、顺序、最多调用数 | batch.json |
| 上游视觉计划和复核依据 | 待实现的边界记录，绑定视觉计划/复核记录/编译器版本 |
| 生命周期状态 | frozen_awaiting_authorization；不表示已有授权 |

旧 batch 格式不被本设计直接修改；新上游证据需要兼容包装并验证后才能接入。
冻结之前再次核验输入指纹，禁止“检查的是 A，冻结的是 B”。
所有冻结文件由程序写入，Agent 不手写成功回执。

## 失败输出与修订

问题报告只需：`code`、`category:semantic|geometry|configuration|technical`、
`planSha256`、`jsonPointer`、相关 ID 与说明。
语义/几何问题回 M2，配置问题由宿主调整，技术问题保留诊断并修复实现。
重新修订计划使旧复核记录失效，必须绑定新版本；不能用旧 reviewed 标志放行。

保存原始回答、计划各版本、失败报告和真实计时。不从写文件前的时钟推算首稿完成；
保存完成后才记录持久化事件。所有阶段不生成媒体；视觉模型请求另计，不称为离线。

### 分组复核补充

固定功能图标随控件/控件组，固定徽饰随主体；突出部分通过素材框保留。
只有明确独立编辑要求、独立内容身份或真实穿插依据才另拆素材。不得跨控件收集固定图标成独立素材。
M2 明确检查此类 unnecessary_material_split，遗漏固定符号优先补归属，不默认新增素材。
不因此合并商品插画或独立货币标记。schema 维持 v5，无新增字段。

### 实验实现说明

experiments/ui-planning-m1 的 --repair-once 已提供一次摘要绑定的记录级补丁合并与结构诊断，
用于规划实验。上述“未实现”指生产局部修订入口与冻结集成；实验候选不自动获得 reviewed
或 productionReady，仍需视觉复核，不构成生产 M3 实现。


## 装饰归属与程序职责

所有 UI 装饰（含分隔线、几何标记、渐变、辉光、固定装饰文案）由图像模型保留在所属素材内。沿用 objects 的 decoration 分类和 materialId，不新增绘制字段。业务标签、动态数值、说明和操作按钮文案与装饰文案按用途区分；不因装饰小字使用普通字体就删除。
程序负责合同校验、已有像素的透明处理、裁切、缩放、归位和报告，不绘制 UI 装饰或文字。诊断标框、棋盘格等仅用于对比预览，不属于交付素材。
显式 `horizontal-frame-slice` 只适用于经 M2 复核、两端装饰完整且中段可缩放的宽卡片/面板框：程序保留等比缩放的两端，只横向缩放已有像素的中段；缺省仍为 `preserve`。分组图在派生后接受视觉审查，原始回执及失败意见不被改写。该策略不能补画缺失装饰或豁免整图视觉验收。
原 surfaceDetails 程序绘制实验已撤销；旧产物保留作历史证据，不改写旧回执。含非空绘制记录的旧计划不能继续执行或无声忽略细节，须修订素材归属并按新规则复核。不会自动重生图。
