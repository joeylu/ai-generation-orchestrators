# Compact visual brief to frozen PNG plan

`brief-request` and `prepare-brief` are offline assets-only entries. They do not
invoke a model, authorize compute, generate images or build runtime components.
The caller still inspects the original image and owns semantic decisions. This
route removes repetitive plan JSON and packing arithmetic from model work.

The host calls `brief-request` **before** asking a model to inspect the image:

```text
ai-ui-assets brief-request --reference reference.png --output request.json
```

It records the real request timestamp, reference fingerprint and canvas. Pass the
same reference and request to preparation after the model returns its brief:

```text
ai-ui-assets prepare-brief --reference reference.png --brief brief.json --request request.json --output prepared-r001
```

The supplied `request.json` is a local measurement receipt, not authorization.
Changed digest/reference, future timestamps and naive timestamps fail. Measured
request-to-submission time includes all host/model/transport waiting; it is not
inference-only latency. Retries with a fresh preparation output retain the same
request start if they belong to the same observation task. Without `--request`,
preparation records only its own synchronous stages and reports requestTiming null.
Never retroactively manufacture a request to claim complete historical timing.

## Brief contract

```json
{
  "kind": "ui_assets_brief_v1",
  "id": "sample",
  "reviewed": true,
  "assets": [
    {"id":"scene","role":"background","region":[0,0,200,200],"description":"Dark starfield."},
    {"id":"frame","role":"important_component","region":[20,20,160,160],"description":"Complete gold border with its corner leaves."}
  ],
  "elements": [
    {"id":"stars","label":"Stars and orbital arcs","region":[0,0,200,200],"owner":"scene"},
    {"id":"border","label":"Gold frame and corner leaves","region":[20,20,160,160],"owner":"frame"},
    {"id":"title","label":"Ordinary heading text","region":[50,40,100,20],"owner":null}
  ],
  "boards": []
}
```

All regions use original-reference `[x,y,width,height]`, never mixed XYWH/LTRB.
Asset order is back-to-front paint order; the background must be first and full
canvas. Each asset has one canonical source rectangle and output size. Optional
`placements:[[x,y],...]` replaces its default placement at the region origin;
all positions must fit the canvas. Nodes/groups, source hashes, routes,
output modes and required null source_asset fields are generated by the compiler.
Repeated placements share a material; no claim of independent texture generation.
For an observed repeated element outside the canonical source, add explicit
`"reuse":{"element":"canonical-element-id","reason":"Reviewed matching artwork and size"}`
to that element. Keep both original observation rectangles. The canonical element
must have the same owner and size and must not itself be a reuse. The compiler
does not infer this declaration from equal dimensions or similar labels.
Planning checks the canonical source, each instance's own destination, and exact
translation with no scaling of the material. Missing, chained, cyclic, differently
owned or resized mappings fail. Distinct textures/ornaments require separate
assets if they cannot truthfully share the canonical art. Arbitrary relocation,
rescaling and deformation remain outside this profile.

`elements` is an independent visual inventory, not a copy of asset IDs. Include
ornaments, attachments and seams. Each material has exactly one named owner;
`owner:null` explicitly means ordinary text excluded under the existing text
policy, not permission to omit arbitrary non-text artwork. `reviewed:true` means
the caller actually reviewed that inventory and its asset descriptions. False
is accepted as a draft input but blocks before freeze. The compiler cannot detect
an omitted visual element or prove a dishonest review flag.

Each asset description states only its desired artwork. Multiple independently inventoried static elements
may deliberately share one asset owner. Prefer this for a connected static panel
when independent editing or state changes are not required: preserve its fixed
ornaments and surfaces in their shared reference geometry. Layer count is not a
quality target. Decide this ownership before board packing; a board of separate
parts cannot preserve their original joins by itself. The compiler does not choose
semantic grouping or prove visual fidelity.

The compiler adds owned
element labels and explicit exclusions for **every** element owned elsewhere,
plus ordinary text exclusions. The same data generates coverage.removedBy. It
does not guess prompt semantics. Explicit ownership overrides broad preservation
language, but a caller must still avoid contradictory or malicious descriptions.
All non-background raw materials use the existing solid #F808F8 key contract;
owned dark artwork is not automatically treated as background.

Optional boards use only `{"id":"symbols","assets":["a","b"]}`. The caller
decides material compatibility; the compiler checks size similarity, computes
native-size shelf packing with margins, limits canvas aspect to 2:1 and keyed
area to 4,194,304 pixels, and verifies with the existing official packer. It
never scales artwork to fit. Unpackable or unlike members require regrouping.
Extraction uses existing relative-cell 1.0, target padding 2 and aspect tolerance
0.15. A computed canvas does not establish provider support or successful output.
Within a board, a slot's exclusions apply to that slot, not its siblings. Target
coverage retains exclusions; intermediate board coverage collapses cross-slot
removals without suppressing genuine owner/self-removal conflicts.

## Budget diagnostics after every correction

`prepare-brief` writes `budget-review.json` during compilation, before the geometry
gate. It reports current `plannedCalls`, `finalLayers`, and same-size ungrouped
board `candidates` with `savedCalls`. These are packable size-based suggestions;
the caller must inspect material compatibility before adding them to `boards`.
Candidates are never applied automatically and do not reduce the reported budget.
Inspect the entire reference edge of each icon/ornament before declaring reviewed;
neither packing nor coordinate containment detects artwork clipped by an inaccurate
observation rectangle.

For a revision, retain the previous report and pass it explicitly:

```text
ai-ui-assets prepare-brief --reference reference.png --brief brief-r002.json --request request.json --previous-budget prepared-r001/budget-review.json --output prepared-r002
```

The report compares `previousCalls` and `change`, and warns when planned calls
increase. Missing prior input is reported as null; it never guesses a baseline
from directory names. Prior report digest and original source identity must match.
Warnings do not require an extra approval and do not block freeze. They must be
resolved or explained in the existing single compute authorization summary.

To diagnose an existing plan without refreezing, use:

```text
ai-ui-assets budget-review --plan plan.json --groups groups.json --output budget-review.json
```

This read-only command accepts an optional `--previous-budget` too. Neither entry
changes existing plans, generation attempts, authorization or prior receipts.

## Output and failure boundaries

Preparation writes original reference bytes, brief, generated plan/coverage/groups,
planning-check, covered plan, optional compiled boards, and an official frozen
batch. `preparation.json` includes `budgetReview`, exact maximumCalls, plan/batch digests and five
timed stages: input, compile, planning-check, board-compile, freeze. Each stage
also writes started/finished records; failures leave failure.json and available
diagnostics. A killed process can leave a started record without a finished one;
this is incomplete execution, not success. Outputs must be fresh directories.

After independent review, request fresh digest-bound user authorization. Existing
authorize-generation/export-loop/preflight/process/recovery/export gates remain.
This route never hands out an authorization or marks human visual acceptance.
It has no Docker, network, session supervisor, deployment or server dependency.
Offline tests do not prove that a new Luna session will plan faster or better.

## Current v2 granularity gate

New `brief-request` asks for `ui_assets_brief_v2`. `prepare-brief` requires v2
by default. Existing v1 inputs can be replayed only with explicit `--legacy-brief`;
the preparation receipt labels them `not_checked_legacy_replay`. The expanded
legacy planning entry and already frozen batches are unchanged. This gate applies
to compact preparation, not all historical freeze APIs.

V2 retains the v1 fields and adds required `granularity:{"units":[...]}`.
Each unit has exactly `id`, `elements`, `basis`, `splits`, `connections`.
Every non-background material inventory element must occur in exactly one unit;
text and background elements are omitted from units. `basis` explains the observed
visual grouping. Preserve one static unit under one owner by default, with empty
splits/connections. Multiple observations can share that owner.

If a unit has multiple asset owners, each owner requires one split declaration:
`{"asset":"frame","reason":"user-request","evidence":"User needs separate editing"}`.
Reasons are `independent-state`, `independent-skin`, `reuse`, or `user-request`.
Fewer calls or more layers are not reasons. Every distinct owner pair requires:
`{"assets":["frame","crest"],"relation":"occluding","seam":"Visible rails terminate behind crest","occlusion":"Crest paints over rails","alignment":"Use original reference coordinates and inspect visible attachment landmarks"}`.
Relations are `joined`, `occluding`, or `separate`; all three evidence strings
remain required, including explicit no-seam/no-overlap explanations for separate
parts. Duplicate or unknown members/pairs and blank evidence fail.

Preparation writes `granularity-review.json`, checks it before budget diagnostics,
board compilation and freeze, and binds its digest into the frozen coverage review
basis. Failed checks generate no requests or media. Preparation also exposes the
review digest/status. A changed brief changes the review binding; existing frozen
plans are never migrated silently.

This checks declarations, not image semantics. It cannot recognize falsely split
units, verify prose evidence, infer all seams, measure generated fidelity, or
approve artwork. Caller inspection remains required; do not subdivide a connected
static panel into artificial units merely to avoid split evidence. No automatic
merging or visual gate bypass is introduced.
