# CLI 转发 Hook 的输入与大回执

图片工具的 PostToolUse JSON 可能包含内联图像，体积大于冻结请求。旧版对所有 Hook
stdin 统一限制为 2 MiB，会在读取已完成图片的大回执时停止，导致 image-post.json 缺失。
即使 CLI 正常结束且原始 PNG 已保存，适配器仍必须按审计失败处理，不能仅凭文件存在
接受结果。

Hook 现在使用两种明确上限：PreToolUse 请求仍为 2 MiB，PostToolUse 回执为 96 MiB。
回执上限对应现有 CLI 单条结果边界，可容纳 64 MiB PNG 的约 86 MiB base64 内容。
读取始终受字节上限约束；超限、无效 UTF-8、截断 JSON 或错误事件类型都终止调用，
不写成功凭据。

后置检查仅接收事件类型、工具名、session ID 和 tool-use ID；图像响应正文不写入凭据
或执行日志。冻结请求和参考图摘要、原始单次保留、会话/调用身份、独占写入以及最终
PNG 检查仍按原合同执行。前置请求不得借较大的回执额度绕过原有输入限制。

消费方须随新的固定源码附件升级，并核对新 Hook 字节摘要与本次启动的确切信任定义。
不要直接编辑已安装 vendor、放宽全局信任或绕过缺失凭据。Web/API 合同不变。
旧的不明尝试保留原始 PNG 和全部记录，不补写历史 Hook 凭据、不改成成功，也不自动
重投；新的真实调用仍需要新的冻结计划和明确决定。

回归使用合成响应和真实本地 Hook 子进程，包含 2.19 MiB 回执、请求边界、有限回执
上限、错误身份、缺失原始保留、重复回执、截断数据及输入图变更，不调用图片模型。
