## 对截图的判断与原因

抽看设置、结算、加载与本地暂停对照：主标题已居中，基础操作主次清楚；结算和加载仍使用通用信息表单式结构，没有因候选skill变成突出结果与主操作的游戏布局。这是审阅判断，不是用户美术评分。

本地暂停唯一结构差异可由现有规则解释：`sectionHeadingVisible`在只有一组且有多控件时，按分组标题是否等于面板标题决定隐藏。基线等组写“已暂停”，因此隐藏；ui-ux-pro-max组写“暂停操作”，因此显示，标题与间距总共增加48像素。单控件在线暂停会始终隐藏分组标题，所以相同文案差异没有改变画面。这里暴露出**自动分组措辞影响几何稳定性**，未证明任何候选稳定改善体验。

生产基础提示明确要求未指定width/maxHeight等留空，由程序负责几何；按钮actionLayout没有显式组内排版要求时为null。首次生成也不开放任意字体、位置或单按钮样式。模型仍可选择分组、外层行/列/网格等，但这些简单请求在本轮都形成单列单组。实验要求候选遵守原合同，因此多数skill的泛化设计建议没有可落地的自由度。不能将这个约束下的结果解释为开源skill本身无效。
