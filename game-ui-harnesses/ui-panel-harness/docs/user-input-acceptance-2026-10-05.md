## 发现的问题

**E10（首轮失败，现已复验通过）：模型误判新增输入能力。** 第一步要求新增单行、非必填、初始为空的角色宣言，
并加入确认提交范围。模型返回 NEEDS_INPUT，声称响应 schema 不含 add-input-row。
按该请求上下文重建并遍历当前原生 schema，可确认 CodexEditDraft 0.3 确实包含
add-input-row，公共 add-row 能力也已提供。这是需求未通过；第二步没有提交。
E02 的同类新增输入成功，不能据此把 E10 记为通过。

**C01：补充回答后的真实调用连接失败。** 第一轮正确询问范围、步长、初值，
保留原面板；超过长度上限的回答被本地拒绝，没有调用模型。
填入明确业务值后，第二轮返回 CODEX_CONNECTION_FAILED_NO_RETRY，未取得可用方案。
它不证明补充生成成功，也不能据此判定业务需求不支持。
零模型调用重放原失败响应，另验证原 Spec、当前输入、事件和撤销历史完整保留，
不重复提交、不应用迟到结果，共 6 项检查通过；这不改变 C01 的整例失败状态。

未执行：**C02、C03、C04、C05、C07、C08、U06、U03、U09、U08**。
“当前值还是默认值”的歧义、冲突需求、缩短输入上限、双击、双窗口、取消仍需要真实验收。
