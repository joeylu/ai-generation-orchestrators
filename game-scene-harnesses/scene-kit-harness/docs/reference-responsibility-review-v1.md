# 参考图职责拆分审图

这里的拆分是把横版参考图的可见体块、景深和编辑需求交给来源生成及 Studio 回拼。
它不是从一张扁平图片自动恢复干净 Alpha 或隐藏几何，也不是固定的层数/物件清单。
本页是 Agent 审图规程，不新增 JSON schema、CLI 命令或自动语义门。

## 先选实际路径

| 路径 | 当前能力 | 不代表什么 |
| --- | --- | --- |
| `coherent` 主链 | 参考审阅、显式观察覆盖、独立原生来源计划、技术接收、回拼与 Studio 审阅；验证 kit 后可用 `scene terrain-deliver` 交付网格/曲线地形 | 不保证忠实重建或最终美术接受 |
| `reference decompose` / `ownership` | 已接受 target v2 的原图上下文、可见标签、片段和坐标回拼 | 包络不是遮罩，像素回拼一致不是职责正确 |
| `reference segmentation-seeds` / `segmentation-import` | 显式 CPU GrabCut 候选的准备/接收；生产者独立运行 | 不是主链必经步骤，不恢复材质 Alpha、隐藏形状或完整资产 |
| `reference prompt-input` / `prompt-import` | 显式点框 CPU SAM2 候选的准备/接收；原候选、重叠和未知保留 | 不提供自动语义接受，不因覆盖率高就可交付 |

后三条是可运行的旧实验工具，不是当前“参考→可编辑素材”的完成证明。
精确参数以 `node scripts/coherent.mjs --help`、`node scripts/reference.mjs --help`
及各版本文档为准。审图不需要运行分割模型。旧说明中的“来源生成尚未实现”只指
其精确提取/忠实回拼分支，不是否定现有 coherent 主链。

## 审图记录：先观察，后对齐现有主体

记录准确原 PNG 摘要、原生尺寸、审图目的（借画风/保留场景意图/按点复原）、允许的镜头范围及
预期编辑操作。用完整原图逐区扫视，再看疑难局部；不要从既有 subjects 反推清单，
否则未规划的大体块会同时从观察和覆盖检查中消失。坐标注明原生/规范视口及映射。
普通参考意图任务优先保证体块职责、前后层次与可编辑性，允许局部比例、跨度和细节
变化。观察记录不等于每项都成为精确几何门；只对用户要求复原或影响玩法/接触的
关系指定硬容差。已有严格合同改用近似目标时，单独记录
[参考意图审阅](reference-intent-review-v1.md)，保留原诊断，不需要为此重新生图。
冻结命名特征前，把坐标叠回准确原图并放大核对：点必须落在所命名的端点、接点或
部件上，不能把旁边重复构件中的一点称为端点。新来源的同名点也要对应相同可见
特征，先固定量测再拟合。若事后发现原标注错误，保留原门结果，按已有坐标勘误
合同另记原图证据；不能改点名、容差或按新图残差挑一个更容易通过的参考坐标。

每个会影响构图、遮挡或编辑的体块单独登记以下信息；数量由画面决定：

| 项 | 必须回答 |
| --- | --- |
| 观察 ID 与定位 | 何处看到了什么？给区域或可辨部件点；不是只写“中景” |
| 可见体块 | 主体、附着小件、支撑/接地点、被裁边；大形也要列，不只列命名道具 |
| 辨识特征 | 主体是紧凑/细长、竖向/横向还是环状？哪些主要色块、材质分区或附着物使它区别于邻物/同族成员？ |
| 朝向与可见面 | 哪面朝镜头、哪侧可见，关键部件向哪边伸出？这些方向是否影响与邻物的关系？光照方向单独登记，不能用“另一侧”代替左右关系 |
| 空域 | 洞口、通道、天窗等由谁的轮廓围出，后面应显示哪层？淡色雾不自动等于透明洞 |
| 景深依据 | 遮挡边界、比例、对比/雾化等证据；分别记局部前后与整体深度，不能只凭上下位置 |
| 职责 | owner subject、来源类型（背景带/独立物件/材质/作者地形）、实例与层；谁明确不拥有它 |
| 编辑需求 | 是否须单独移位、缩放、隐藏、动画、换皮、重排或改变碰撞？重复实例能否共享源 |
| 可见性/推断 | 已见、局部遮挡、画框裁切、无法判断分别写明；隐藏部分另列假设和影响 |

用于适配来源尺寸的包络也应纳入自有外伸部分与支撑，不能只圈中心主块。遗漏这些
部分会让后续等比适配缩错整体，不能把它误诊为生成器改变了比例；未见部分仍按
推断另记，不把观察包络当作完整 Alpha 遮罩。

同时建立**局部关系表**：`前方体块 → 后方体块`，附上发生区域、应保留的可见特征、
证据/不确定性，以及两者的 owner。接触另记“谁支撑谁、接点何处”，不要把接触
等同遮挡。实体洞口和其后被看见的景物是两份职责，不能在洞内画死邻层。
雾、反射或透光若跨多个来源，明确采用来源自身的远近外观、独立支持的叠层，或
记录能力缺口；一张完全在后方的天空图不能使前方不透明物件雾化。

空域的后方职责要登记到完整可见范围：分别核对上部、内部和底部应露出什么，
不能只凭“有一个远景源”判定已覆盖。记录轮廓围出的开口与后方持续体块的不同
owner，并在默认镜头和声明的镜头范围内复查。天际轮廓源不自动承担下方纵深，
同理窗洞背后的景物、岩隙内壁与拱口后的地面也不能漏掉。复用现有源补充实例是
一种待审的摆放方案：保留独立实例与推断记录，检查重复轮廓、截断底边、特征尺度
和遮挡；没有这些证据，复制更多层不能算职责已经解决。

`parentRole` 是职责类别，不是最终绘制次序。用真实 layer、zIndex、实例顺序及
parallax 检查关系；“同为 far”不保证可互相穿插。视差也不会自动降低对比。

## 合并与拆开

**可以合并为同一来源**：各部分共用深度/视差和变换，不需独立编辑；对所有外部
体块具有相容的遮挡顺序，连接/开口在素材内部可保留；合并后没有丢失接地点或
被遮区域的表达能力。例：固定设备的壳体和不可动的附着螺栓。说明合并理由。
同材质、相邻、同 layer 或同名词都不足以支持合并。

冻结前检查实际提示是否保留这些判断。材质家族不能额外指定画面没有的城市、山体
等主体；单体模板也不能删掉已明确归属的组内构件。普通意图任务可显式使用
[来源内容职责](source-content-v1.md)，不为了保留一个固定组而增设逐点复原门。
已绑定的精确结构合同继续保留，职责选项不能替代其验证。

**必须保留独立来源或可独立放置的部件**：有不同视差/动画/编辑目的；一个部分
应在外物后、另一个部分应在外物前；关键负空间、接触或主要特征需单独控制。
同一完整图像不能靠一次 zIndex 改变完成局部穿插。若 A 的两个部件分别在 B 前后，
将 A 分成可单独摆放的部件，或使用已有且经验证的遮挡能力；不假设 Studio 有蒙版
或深度缓冲可替代拆分。不支持的能力在冻结前列为阻断。

**共享源不等于合并实例**：相同外观的多个物件可引用同一 PNG，但保持独立实例、
变换和排序。非对称轮廓、独特接点或不同隐藏延伸不能用镜像/复制假装完成。
一个 PNG 中的左右双岸虽可有透明通道，仍不能独立调节左右岸；需要分别调节时应
拆开。反之若两侧确实固定同层且无需独立编辑，可作为一条带，不强制一物一图。

**材质不拥有地形轮廓**：可玩台面/碰撞由作者地形与表沿负责，材质源只提供外观。
同样岩石或金属的远处大形仍需景深来源；不能把所有可见面交给材质场，也不能把
可编辑平台烘进背景带。附着的小支撑与另一层主导地貌要在双方 scope 中互相排除。

在冻结前核对可玩物件的实际摆放能力：自由环境实例、整块平台皮肤和可刷地形的
缩放/碰撞规则不同。若主要体量只能依靠当前不支持的变形才能成立，先修订来源
或作者几何方案，不能假设 Studio 会只改图片而保持玩法正确。非对称物件记录主块
朝向与附属件延伸方向及其影响；允许局部变化时，按配重、接触和编辑用途判断，
不把每一种左右差异都升级成必须重生的错误。
审阅来源措辞时也核对体量：“薄、紧凑、低矮”等限定必须有参考或设计依据，不能
为了生成方便而削弱已见主块或独立物件的视觉焦点。这里检查大形职责，不要求逐点
复原轮廓。
登记的接触高度不落在地形网格上时，核对现有曲线等表达能力，或明确审阅网格近似
是否仍保持必要接触；不要仅靠背景颜色掩盖取整后新增的空隙。

## 看不见的部分

将已见特征与假设分行：遮挡者/裁边、可能延伸、为何需要补全、可允许的设计范围、
移动后可能露出的接缝，以及复查办法。写入 scope 的补全要求必须标为设计推断，
不能为看不见的底端编造“测量坐标”。观察到的遮挡边缘不是物件的物理终点。
只需保持可见身份且不影响关系的隐藏小延伸可明确假设后规划；若未知部分决定
主要支撑、洞口连通、穿插或独立编辑是否可行，先解决设计/能力问题，再冻结。
已有结构门要求的特征对应若缺失或不确定，仍按原门阻断，不能用假设代替测量。

## 交给执行链，避免只留在审图笔记里

| 审图结论 | 实际承载位置与检查 |
| --- | --- |
| 主体/数量/层 | requirements 与参考分析 instances；缺主体时走受支持的同项目设计修订 |
| 每源内容、附着支撑、补全假设和邻层排除 | 最终 `sourceScopes.content` / `exclusions`；适用时显式 `scope-owned-support-v1`；检查编译后的完整 prompt |
| 来源自身的外观/雾化 | `source-owned-appearance-v1` 的每源规则；必要时显式选 `reference-atmosphere-v1` 提示分支；不要只藏在不会继承的共享 style/observations 中 |
| 原图观察归属 | `requiredObservationIds`、`observations`、`assignments` 的准确原图覆盖检查；每个体块有清楚 owner，多个部件共享源仍分别登记 |
| 要保留的来源内部结构 | `referenceStructure` 的命名部件、原容差与检查；带状源按需使用 band relations/guide 和完整画布标定 |
| 跨来源的前后、接触、独立编辑 | 审图关系表→composition/作者图的实例与绘制顺序→准确最终图上的 placement 与实际 Studio recomposition review |

观察覆盖 JSON 只接受既有字段，不把本页关系表硬塞进去。也不要把别的来源的
部件伪装成自己的 structure feature。当前覆盖器检查文字映射与层/parent；
`features-review` 检查提交的部件量测；placement 检查标注区域。它们都不自动
识别“桥后有坡”或证明关系表完整，Agent 必须逐条对照最终 scope、完整请求和画布。

检查**编译后的参考用途**，不只检查 brief 字句是否被保留。如果任务要求同源内部的
部件比例/排列，最终提示仍说参考只供外观，则文字覆盖 pass 仍不足以冻结；先用
受支持的 `referenceStructure` 或 band relations/guide 明确绑定，再重编译审阅。
反过来，已经决定固定同层的背景组不必因含多座桥或多栋楼就拆成多个来源。
若新的独立组确实包含多个自有部件（包括同侧复数部件或两侧部件），按
[结构合同](reference-feature-layout-v1.md)为对应 asset 显式选择
`compositionProfile: 'source-owned-feature-group-v1'`，防止旧单体模板把复数/两侧措辞当
成无须保留的场景语境。逐项检查所有拟冻结来源的最终提示，不能只修最显眼的一组；
它不允许把需要独立编辑或穿插的物件重新合并。

物件身份不确定时，先记录确定可见的形体与职责。例如一条横向构件可能是屋檐或
连廊，不能据此编造通行连接或要求准确桥数；身份未知但不影响本轮静态职责时可
保留不确定性，影响支撑/连通/编辑目标时才阻断。相接的独立物件要说明各自接口
归属；自有挂架可以随物件，宿主墙面及投到墙面的阴影不自动成为该源的像素。

新 coherent 参考审阅显式使用 `--defer-source-plan true`，先 `source-review`，
再 `observation-coverage`，通过后才 `advance`。临时 `source-review --briefs` 的
预览不会自动采用改动。独立修订来源要对准确新 requirements/scopes 重跑覆盖，
不能借旧 pass。参见[覆盖检查](reference-observation-coverage-v1.md)及
[同项目设计修订](observed-reference-design-v1.md)。
初始来源预览不是已有批次的准确修订计划。局部替换必须核对当前父批次、准确原图、
共享视觉合同与已有结构义务；未替换来源保留原摘要。不要把预览中重新编译的共享
合同直接混入历史批次，也不要为通过批次校验而关闭约束或重建工作流。

以下情况停在**受影响新计划冻结之前**：主要体块/空域无 owner；职责互相包含或
排除；必要独立物件被不可拆合并；排序无法实现局部遮挡；关键隐藏关系尚无可行
设计；当前合同无法表达需求；参考/范围/结构证据不一致。修订输入或设计后重审，
保留旧工程和失败记录。覆盖 pass 不能豁免这些审图阻断。

接收后做双向职责核对：清单要求的自有部件是否齐全，以及图上实际出现的每个主要
部件是否确实归该源。相似的横向、竖向或成对形体不能仅凭外形归组；观察表中须
以可辨别的身份/附着关系区分自有构件与相邻独立物件。位置接近不转移职责。
发生混入后，修订审阅须列出易混淆双方的可见辨识依据、各自 owner 与附着关系，
并检查这些区别是否进入准确请求。禁止整个形状类别会误删合法的自有部件，
只重复物件名字也不足以说明两者的区别。移除前方物件的职责，不等于在后方来源
上挖出同形 Alpha 洞；隐藏处按已见的自身表面或真实空域做明确的设计推断，不另
造替代连接来填位。若无法确定主要开口或支撑是否存在，仍须停在冻结前。保留原
结构、原容差及接收后的双向核对；更具体的请求只是待检验假设，不是修复证明。
邻源像素一旦被画入，明确把对应结构检查记为 `fail`（无法确认时为 `uncertain`），
阻断采用与回拼；不能因为透明 PNG、文字覆盖或几个命名点拟合通过就声明职责通过。
不要先把错误源回拼、藏到其他层下面或裁掉越界物件来制造合格结果。若继续已获
准确授权的其他独立来源测试，记录其不依赖失败源，且整批回拼仍被阻断。

接收后看完整原生源与透明开口，再核对实际 Studio：默认镜头及声明镜头边界下，
必需部件是否仍可见、接触是否成立；分别隐藏/移位关键物件，确认编辑独立性。
整图比较先统一显示尺寸、视口和取景映射。材质尺度同时看有代表性的大形或完整
重复周期，不能只凭一个小螺栓或不同缩放的截图判定密度失真。把可观察的板块行距、
大形尺寸与主观重复感分别记录；若同尺寸复核推翻初判，追加更正，不为维持旧判断
而修改已经合适的素材。
将差异归因到来源职责、原生内容、位置/尺度、绘制顺序或外观，不以增加导图、
放宽阈值、复制旧层或调色宣称修好了错误职责。技术通过、Agent 审阅与人类美术
接受分别记录；新计算仍需要新准确计划、digest、持久预约和单次调用。
同源结构拟合失败时，先核对特征对应，再比较有符号的相对位置、距离和宽高比例。
整体位移不改变相对关系，正的统一缩放不改变方向和比例；透明留边也不能修正它们。
如要断言任何摆位都不可行，应给出含原容差与量测不确定性的依据，而非仅引用一次
拟合失败。生成失真本身不是拆分理由：仍按编辑、视差和遮挡需求判断拆合；切换
导图、背景带或设计修订前核对实际项目版本、坐标合同与能力，不能只更换提示词。
独立固定组可显式使用[素材画框导图](source-frame-guide-v1.md)，但不能为了获得导图
强加连续背景带的左右/底部绘制覆盖。画框需容纳登记的所有体块与特征；未见补全区
单独标明，参考窗口里的邻源仍须排除。若原图特征坐标经独立复核被修正，将同一
修正回执带入新 source scope、导图和回拼；不要让生成仍按旧坐标、回拼却用新坐标。
特征覆盖不能只选最外侧或最高/最低的几点。会分割主开口、改变内部遮挡的横件、
支撑或中部体块，也要在冻结前登记可见位置或可审阅的相对位置关系。功能身份不明
仍可登记已见位置，不需要先猜成桥、屋檐或可通行平台。生成后逐项核对未标记体块；
外侧几点拟合通过不能代表内部结构通过。若已漏记，只追加诊断和失败证据，不改写
冻结合同；下一份结构设计另行审阅。合成工业框架回归说明四角完全吻合、内横件
错位时，准确的开口检查仍须阻断；程序不会从像素自动补足错误的审图登记。
对于已有 owner 的漏记特征，可通过单独审阅的[追加特征合同](reference-feature-supplement-v1.md)
加强新请求：保留原结构和坐标修正，追加新 ID 的位置/检查，重新审阅导图，并将同一
追加摘要带入 v6 回拼。它不能换掉旧点、放宽原容差、改变拆合职责或接纳旧失败图。
运行时的 `ready-to-deliver` 只表示已收齐通过技术检查的来源，不能替代上述审阅。
提示约定的留白、完整性与图内职责也不都由 PNG 技术门检测；分别记录实际偏差，
保持原 QA 结果与原 RGBA，不把补框、调色或 Alpha 清理当作默认修复。
独立素材通常需要透明边界来容纳完整轮廓与柔边，但固定 12% 不是通用验收门。
按[来源留边合同](source-framing-v1.md)为新请求选择适量留边；旧提示的比例偏差保留
为历史观察，不能单凭低于该比例拒用完整且技术有效的来源。参考中的取景裁切、
源图完整性和回拼后的视口裁切是三个不同问题；补全的端头若在视口内露出，应另记
为推断部分的摆位差异，不能靠改源图 Alpha 隐去。

冻结前还要检查所有“延伸到底部、贴边、出框”等措辞指的是哪一个画框。对完整独立
来源，参考中越过画框的构件需要明确的自有端头推断；源 PNG 容纳完整端头与柔边，
回拼再按可见特征定尺度并由视口裁切。不能让同一 brief 同时要求完整轮廓和画到
源 PNG 底边，也不能为了闭合而增造共同地板、墙体或其他 owner 的连接。若设计
确实需要有意切断的连续来源，先选择支持该角色的有限覆盖合同并审阅其镜头域，
不要在技术失败后把原独立来源追认成带状来源。源图实体被截断与微弱 Alpha 尾迹
触框分开诊断；补框只能沿用明确资格，不能恢复断掉的构件。

## 局部替换后的复查

可编辑地形还需按[零生图接合诊断](terrain-join-diagnosis-v1.md)区分连续主体、表面
覆盖/附着岩肩、原生上角、裸侧壁与下缘/下角。桥洞的天花板是下缘职责，洞后景深
是另一来源职责；不要把二者与地面顶层混为一组。上角局部覆盖不能扩成完整平台。
发生叠厚或岩块尺度不一时，先隔离实际绘制组，再把结论传回准确来源 brief 或原生
量测；不同来源的组内画法差异不能仅靠缩短 shared cap、移动整体或加密纹理消除。

只更换一个来源时，以当前父批次和实际新计划为准：记录哪些主体/观察改变，哪些
来源保留原摘要与原结果。把新的自有内容、邻源排除和隐藏补全从 scope 对照到
冻结 prompt，再核对预约返回的准确请求及原图输入。旧工程摘要或初始 subjects
清单不能代替这一步；新的文字覆盖只证明本次检查的观察，不自动覆盖全批历史。

新来源接收后分别回答：

1. **图上职责是否正确？** 对照完整原生来源，检查自有体块与混入的邻源；邻源
   的大形被移除后，仍须保留本源合法的小附着物，不能按共同名称或形状一概排除。
2. **新画框如何影响回拼？** 完整轮廓、推断端头及比例可能已经变化。旧变换与
   层序可能只是掩盖了原来的混层，须回到已登记的前后/接触关系重新判断。只在
   现有能力内调整摆位、统一缩放或排序，不靠重新画入邻源、裁剪或调色补回关系。
3. **实际视口仍成立吗？** 在默认镜头和声明范围内检查开口上部、内部与底部，
   再移动/隐藏相关独立物件并撤销，核对其后真实存在的来源与其他物件未被带动。
   分别记录素材自身完整、回拼中可见连续和编辑后可恢复；任一项不能替另一项。

完整来源的可见比例不能只由粗包络决定：推断端头和微弱 Alpha 尾迹都可能改变
包围框。用实际可见体块、接地点和附属物相对位置校准，保留源 PNG；也检查编译后
的平台位置，网格吸附与初始避让可能使它偏离预期开口。若现有 Studio 命令可以
恢复职责关系，用可撤销的作者编辑并保留初始候选、命令和新地图身份。编辑后重新
截图和导出重开，不能继续把旧候选截图或原交付摘要当作新地图的证据。
原图映射产生小数地表端点时，可显式选择[向内整数校准](coherent-surface-calibration-v1.md)，
保存原观察及有界近似；不能为适配编辑器而静默改写已接受的参考记录。

对近似参考任务，河曲、枝叶数或非功能性局部比例不同可作为已记录的变化，不追加
逐点一致门。技术失败、邻源混入及丢失必要编辑能力仍分别处理；符合已有条件的
确定性准备沿用其准确预览/采用合同，原生失败保留。通过后的范围写到实际检查的
视口与操作，不声称任意移动后仍无接缝，也不替代最终人类美术接受。

允许近似不能抹掉主体辨识特征：紧凑体块变成长挡板、竖向容器变成横向提箱，或
主体材质被邻接建筑的大块配色替代，都须作为单独差异审阅，不能仅以“仍是同类
物件”通过。先记录参考中可见的主轴、大形和材质分区，再判断变化是否影响身份、
构图或用户目标；这不是统一宽高比阈值，也不要求螺栓、接缝或小尺寸完全一致。
同族多个实例若外形不同，分别表达其辨识特征与原图定位；不要把同一泛化 brief
复制后期待模型自行挑对成员。现有 subject 级覆盖无法表达时，拆为不同 subject，
或在支持的单项修订中分别冻结 scope；不得偷偷修改旧请求或来源摘要。

允许近似也不自动允许镜像或换面。对会影响画面连续性的正侧面、开口、悬臂或
材质分区，明确写出观察到的左右/前后关系；物件位于画面的哪侧与物件自身哪面
可见是两件事。受光方向另外记录。若新来源换面，单独审阅它对原设计的影响，
不能仅以同族、色块齐全或 Alpha 合格代替判断，也不能因漏写朝向而追加逐像素门。

区分摆位、组内形状与单体造型三种偏差。先在保存副本上仅平移/等比缩放，观察
已登记的大体块与开口关系是否改善；保留比较基线和命令，不覆盖用户当前画布。
若多个组内特征需要不同方向的修正，单次组变换不能解决它们；若原生单体已经
变型，也不能靠不等比挤压或包络适配声称还原。被裁边的参考只证明可见部分，
新增完整端头仍是推断，须检查其是否误露在回拼视口内。

## 不同构图的离线练习：工业装卸台

合成图由 `tests/helpers/reference-responsibility.mjs` 确定性绘制，测试使用数据与替身，
不调用生成器。构图是左后仓库、居中装卸机、横向甲板与右侧独立货箱，没有溪谷。

| 观察 | 拆合结果及理由 |
| --- | --- |
| 仓库屋面与固定墙体 | 同深度、固定变换，无独立编辑需要，可以合并 |
| 装卸机后梁与前立柱 | 在货箱两侧形成相反遮挡，必须分部件；不能整机一次排序 |
| 货箱 | 保持独立移位，位于后梁前、前柱后；不能烘进甲板材质 |
| 悬钩 | 独立动画/隐藏需求，不能并入静止梁；被货箱挡住的钩端标为推断 |
| 甲板 | 可玩轮廓和碰撞归作者地形，金属材质可复用；不负责后仓库 |

可行顺序为仓库→后梁→悬钩→货箱→前柱（甲板接触另核）。把后梁与前柱合并时，
无论整组排在货箱前或后都会错一处；离线用像素探针复现这一点。同一正方货箱
若有多个实例可共享来源，但不因此把它们变成一个不可独立操作的图组。
这证明拆分依据是局部关系和编辑目的，不是某种场景必须具有的物件或层数。

## 连续地面与窗洞：室内拱廊反例

`tests/helpers/reference-gallery.mjs` 提供横向室内构图：一条连续地面、两个开口、
后拱架、可移货箱、前柱和独立吊灯。它没有峡谷或悬台。窗洞上部看天空、下部
看庭院树丛和地面；不能把完整洞口都交给天空，也不能把窗框和窗后景物画成一源。
后拱架、侧墩和后窗台可以合并，前柱因遮挡货箱而独立；静态合并和独立编辑的
判断仍取决于用途，不因为画面出现机械或灯具就额外要求动画拆分。

`tests/reference-gallery.test.mjs` 验证这个构图只规划实际登记的七项来源，不注入
默认悬台；窗后下部漏分配会被观察覆盖检查拒绝，最终来源提示和冻结重放保留
职责、排除项与隐藏补全假设，未授权的来源不能预约。另有只保留树冠、丢失窗下
庭院的合成视觉反例供 Agent 审图；程序没有把这个像素判断升级成自动语义门。
同文件还验证已接收来源的单项修订：新庭院职责、排除和推断进入新摘要及预约请求，
其他六项保留原计划和结果；旧计算决定不能授权新图。合成 PNG 仅验证接收与状态，
不证明它遵守庭院语义；真实来源和实际回拼仍由上述审图负责。

`tests/reference-gallery-recomposition.test.mjs` 使用分别绘制的完整合成来源，经正式
派生、kit 编译和编辑器检查窗后下部、货箱/后窗台/前柱的遮挡及完整柱脚；移位与
移除后检查露出的后景，撤销和导出重开保持作者内容。样本地面不在网格行上，显式
选用已有曲线地形合同，避免取整产生虚假的离地空隙。故意漏掉下部庭院的来源仍
可通过文字覆盖和 PNG 技术门，但不能通过这个人工定义的像素关系用例。已知合成
颜色的探针只验证该用例，不是自动理解任意图片的语义门，也不要求真实参考逐点一致。
`tests/browser/reference-gallery.test.mjs` 将同一候选交给实际 Pixi Studio，核对这些
关系、移开物件后的后景、撤销后的逐像素恢复以及浏览器 HTTP 导出与 CLI 包的一致性。
它已包含在 `npm run test:browser` 的现有发现范围中；单独运行可用
`node --test tests/browser/reference-gallery.test.mjs`。仅使用合成来源与软件渲染，浏览器
依赖由既有测试环境提供；运行本用例不下载浏览器，也不调用分割或图片生成服务。

真实样本复盘时还要区分“新观察表发现旧 brief 未明确登记”与“旧运行当时检查
失败”。新增清单得到 fail 只说明当前新计划尚未满足这份清单，不回写历史审阅。
原生来源画入邻层主体时，即使旧回拼用排序遮住了重复，也须保留该职责偏差；
下一份新请求通过排除项和自有内容说明边界，不能拿旧文字覆盖 pass 代替审图。
