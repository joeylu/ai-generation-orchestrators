# 多卡片按内容选择构图

新生成默认目录为 `modern-readable-game-card-layout`，16主题0.33.0／0.33.1。属于生成规划预设更新，继续使用原有row／grid／column布局和Compiler0.45；渲染及保存包格式未变。旧目录、保存包和真实结果不自动迁移。

- 设置、暂停、简单确认保持紧凑单列，普通单列约420、按钮菜单约360。
- 多商品、多任务、多成就或角色卡片面向桌面／横屏时，优先用完整section排成两三列：两三项可用row，更多项可用grid。420是单列基础宽度，不是整块面板的宽度上限。程序依各列完整文字和控件测量宽度，正文／按钮24、主标题32不缩小。
- 每个条目的数据、进度和相关操作仍在同一底板内。单个List不因包含多个选项就强行拆成卡片；设置类别也不按控件数量自动变成商品卡片。
- 明确手机、竖屏、单列、列数或尺寸要求优先；模型在这些目标下选择相应的column／row／grid，不改写原文、顺序、动作和默认值。
- 多卡片集合允许滚动，不把所有条目按钮都在第一屏作为统一成功条件。按目标视口检查完整文字、可达性、实际滚动／点击及事件；紧凑确认框的两个选择仍须初始可操作。

当前是固定画布交付，视口只会整体缩放，没有运行时自动断点换列。因此桌面多列与明确手机单列是分别规划的布局，不能把同一个宽画布缩到375后当作手机适配通过。已有原始报告的窄屏观察和首屏失败保留，不倒改旧结果。

本轮以刚完成的10份真实原始结果作离线对照；仅明确调整商店三列、任务两列，原文、字体、分组、顺序、行ID、状态、素材与事件保持。成就仍保留原来的List，内容偏简问题独立保留。新增模型调用0，新规划默认尚未真实模型复测；Unity原生未执行，rc.7尚未发布。
