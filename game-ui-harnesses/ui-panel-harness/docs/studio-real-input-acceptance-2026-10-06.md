## 三项真实失败

1. 标准控制设置 `eval-controls`：`CODEX_PROPOSAL_INVALID`，
   校验码 `INTENT_COUNT`，位置 `$.panel.body.children`。
   模型提供的容器子节点数量不符合公共合同。失败原始JSON未作为合法产物保存，
   只有其摘要和类型化诊断；不能据此断言具体返回了多少个子节点。
   口语版同类需求成功，但标准版这一项仍然失败。
2. 口语背包筛选 `casual-inventory`：`CODEX_CONNECTION_FAILED_NO_RETRY`。
   只启动一次CLI，生产回执中的usage为null，无法据此推断服务端是否已计算或计费。
   没有重新提交。标准背包成功不能替代这个连接失败的结果。
3. 连续修改 `D09`：第一步标题及高度上限修改通过，第二步修改默认值时返回
   `EDIT_CONTEXT_MISMATCH`，位置 `$.contextSha256`。
   模型方案没有绑定当前修改上下文，公共校验拒绝，当前面板保留。
   没有修改回传摘要、重试第二步或用手写补丁替代它；依赖第二步的第三步未调用。

另有检索问题：口语版画质、控制、无障碍、商店的slider配方漏命中，
两组配方命中分别16/16、12/16。它们都通过了生成，原因是完整控件目录仍在上下文中。
这暴露了“能拖的条”等说法的词法检索覆盖缺口，不能把检索漏命中和模型失败混为一类。
