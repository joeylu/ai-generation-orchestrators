# 本地 UI Studio

本文描述当前本地入口。Studio 仍使用带图预设或上传参考图；`ui-chain-components-v0.1.0-rc.2` 新增的文字/风格→参考 PNG→组件流程由公共 CLI/API 提供，见[组件流程](component-pipeline.md)，本网页没有新增文字起步 UI。逐节点输入输出、人工验收点和失败恢复见[验收指南](acceptance.md)；历史阶段结果保留在[执行记录](execution-plan.md)，不以旧端口或旧项目数量推断当前状态。

## 启动

在本 Harness 目录安装锁定依赖并构建模板、合同：

```sh
npm ci --include=dev --ignore-scripts --no-audit --no-fund
npm run templates:build -- --browser chrome
npm run contracts:build
node scripts/studio.mjs work/studio/project.json 4310
```

模板构建可选择已安装的 `chrome`、`msedge` 或 `chromium`，不会下载浏览器。服务仅监听 `127.0.0.1`；打开 [组件项目库](http://127.0.0.1:4310/#library)。端口被占用或不可用时更换最后一个参数，并在浏览器打开相同端口。重启前先核对没有运行中的任务。

Windows 完成上述准备后，也可双击根目录的 `Start Studio.cmd`，默认端口为 4310；命令行执行 `"Start Studio.cmd" 4311` 可指定其他端口。启动器只做本地 Node 与端口参数检查，模型适配器仍需在网页预检，再对当前计划确认。它不配置登录资料，也不替用户确认生成。

如尚无启动配置，创建 `work/studio/project.json`：

```json
{
  "version": "0.1",
  "name": "UI Studio",
  "artifacts": [],
  "tasks": []
}
```

这是本机入口配置，不是生成交付清单。新配置可从空库开始；已有 `work/studio/projects/` 项目仍会由程序发现并核验。不要向公共文档、夹具或导出包写入本机登录资料、私人路径或模型服务配置。

模型调用使用现有可选适配器及其当前登录环境。网页预检失败时修复当前运行环境，再重新检查；预检通过不保证远端连接必然成功。启动服务本身不授权生成，不要用历史验收脚本或通用确认参数代替当前计划确认。

## 日常操作

1. **组件项目库 → 新建组件项目**：填写名称，选择六种带图预设之一，或上传 PNG/JPEG（最大 8 MB）；可选补充描述。预设图与实际输入校验相同摘要。
2. **材质选项**：默认开启“生成标题与面板纹理”，计划为 S01–S04 的 4 张组件图集 + S05 材质图集。当前模板修订3合计32个基础部件（含两态正方形格子）+3个材质；关闭时为四图、32部件。旧修订2仍为30件。旧草稿缺少 `materialGeneration` 字段时继续四图，不隐式增生成量。
3. **生成组件库**：先保存冻结计划，网页展示本批范围和摘要，确认后才调用。同批默认最多两张并发，每张最多一次；取消不生成，已保存项目仍保留。纯文字自动生成参考图不在此网页入口提供；新公共 CLI/API 的参考图生成、人工接受和图集第二次确认另按[组件流程](component-pipeline.md)执行。
4. **制作进度**：按图显示等待、提交、接收、失败和已记录耗时；图集收齐后自动完成本地定位、拆分、切线、安全区与组包检查。启用 S05 时还会提取并绑定标题、分组及面板材质。接收数和本地步骤数分别显示，不推算模型剩余时间。
5. **组件画布**：试玩 16 类组件，核对文字、状态、材质和尺寸变化。左侧定位，空白处滚轮缩放，空格/中键/平移工具移动视图；组件内部优先处理其交互。相机及试玩值不写回作者文档或导出初值。
6. **面板生成台**：选择可用组件、预设或自定义需求、16:9 / 9:16。程序冻结皮肤摘要和方向，网页确认一次面板模型调用。预设含 ui-reference 五类八状态及独立仓库入口；自定义范围见[自定义面板](custom-panel.md)。
7. **面板作品库**：核对内容、状态、组件版本和交付，打开预览或画布编辑。失败、需补充需求、结果不明的任务也保留；不要把同名历史失败卡当成最新成功结果。

仓库入口由 AI 输出标题、物品名称、数量、槽位与初始选择，默认 5 列 × 4 行、行列各 1–32、合计最多 144 格；消费者冻结程序网格及比例，检查自然网格两轴不超过 4000 逻辑像素。新建使用固定格双向滚动，旧文档保持原布局。未提供物品时创建空仓库，只有明确要求才设计示例。已接 context 0.12 / intent 0.13；无物品图集时以名称展示，未知图标资产和未支持的业务语义会拒绝。详见[仓库面板](inventory-panel.md)。

空库没有可用组件时，面板生成被禁用；先完成组件制作。导出/导入项目草稿只保存用户输入，不提交模型。旧示例与历史产物不作为空库起步的必需资产。

## 确认、进度与恢复

整批图集、单张补图、面板生成和补充需求继续生成都使用网页内确认，绑定各自不可变计划。取消、Esc 或切换页面不提交；结果不明时不自动重投。模型已可能接收请求后，不用重复点击或重新准备相同输入绕过记录。

图集接收分母来自实际批次：四图为 `N / 4`，带 S05 为 `N / 5`。本地通常为五个步骤组：核对组件原图、定位、拆分与切线、安全区、组包与组件检查；材质提取绑定包含在末阶段。扩展步骤按真实 DAG 展示。计时只使用已有时间戳，程序结束不代表外观接受。

缺图优先点“检查并恢复已返回图片（不生成）”：只核验已保存图像和调用证据，成功显示“已恢复接收”。没有可核验图片时保留原因。补图使用“仅补生成 Sxx”，准备新计划并重新确认一次，只生成缺失板，保留本批其余图片及所有原失败记录。S05 也使用相同边界。

本地暂时性错误可按[恢复策略](local-recovery.md)有界继续；质量、证据、工具版本问题停下显示原因。旧项目未启用自动处理时不加入自动恢复。已有完成包不因重启而重建。不得手改回执或把失败改成成功。

面板返回澄清时，在该任务中“补充需求”，保存回答后准备新计划、再次确认；原需求、问题和历史结果保留。重启打断的模型调用不自动重投。完整定位方法和恢复选择见[验收指南](acceptance.md#失败与恢复)。

## 面板预览与编辑副本

交付校验完成后，当前等待页面可自动打开对应预览。中途离开、切换组件或编辑新需求时仅提示完成，可从作品库打开；失败或澄清不跳转。

预览默认“当前已保存布局”，可切换“原始生成”。没有副本时显示原始布局。画布编辑可修改受支持的尺寸、自由位置、显示文字、字号和颜色；自动布局中的位置仍由布局管理，需明确转为自由布局才能直接移动。点击“应用到画布”只改当前草稿；“保存编辑副本”才写入独立修订。撤销、重做、恢复生成布局和试玩相互分离。

返回预览或重新进入编辑会读取对应版本的最新已保存副本。版本选择在当前标签刷新后保留，草稿与试玩值不持久保存。并发保存冲突会保留本页调整并提示，不覆盖较新修订。冻结的原始 HTML、ZIP、计划和清单不随副本变化；编辑 JSON 从画布编辑入口下载。

预览与编辑使用对应冻结皮肤和合同快照。当前配置更新不会改写旧作品的摘要；来源文件被改动会停止。更多手势、布局与字段边界见[面板画布编辑](panel-size-editor.md)、[布局合同](layout-contract.md)。

面板可移到回收站并恢复，不删除原始磁盘交付；运行中不能删除。动效为独立的原样、轻快、精致、稳重配置，分别按面板或组件版本保存，不重新生成素材；减少动态效果设置仍生效。

## 维护与验证

| 内容 | 位置 |
| --- | --- |
| S01–S04、S05 模板 | `configs/skin-template-set.draft.json`、`configs/material-template.json` |
| 组件配方和使用角色 | `configs/component-registry.draft.json`、`configs/skin-usage.draft.json` |
| 风格预设 | `configs/studio-styles.json`、`assets/studio-styles/` |
| 字体、间距和主题基线 | `configs/studio-metadata-profile.json`；[文字可读性](text-readability.md) |
| 图集并发与本地恢复 | `configs/skin-generation-execution.json`、`configs/local-recovery-policy.json` |
| 模型与规划兼容 | `src/panel/planning-client.mjs`、`configs/planning-compatibility.json` |
| 项目输入、批次和流程索引 | `work/studio/projects/<UUID>/`，程序核验后关联，不手改生成状态 |
| 本机入口配置 | `work/studio/project.json`，与交付清单分开 |
| 材质合同、导入与已有包升级 | [分层材质](skin-surfaces.md) |
| 运行时显式升级 | `scripts/studio-upgrade-components.mjs`，复用皮肤、检查新消费包并保留旧版本 |

拆分允许预留槽位偏移告警，但实际裁切重叠、归属冲突、缺失主体仍停止。填充完整矩形的切线回退由 profile 明确控制并保留证据；程序不会重画原图。渐变拉伸和复杂纹理仍须人工复核。

`npm test` 为离线回归；`scripts/studio-check.mjs` 为隔离模型替身的浏览器检查，需要离线构建的独立 `--fixture-config`。使用方法和夹具配置以[验收指南](acceptance.md#离线回归)为准，不要求真实模型成功记录。真实生成验收在网页逐次确认，不运行旧自动真实验收脚本。公共文档不预填某台机器的通过次数或真实美术接受结果。

本地能力不包含部署、账号、数据库、队列、多用户协作。程序检查通过仍保留 `visualAcceptance: unreviewed`、`productionReady: false` 等候选语义，不能把它写成美术接受。
