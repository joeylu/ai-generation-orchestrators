# 资产定位与切线核对工作台（内部排查，默认隐藏）

用户已明确要求尽量减少手动调整。此工具不是用户常规操作步骤，不在默认流程中展示或主动要求用户逐件调参。仅在具体资产问题排查时按需使用；正常交付进入统一组件验收页。

```powershell
npm run assets:workbench -- build
npm run assets:workbench -- serve
```

固定本地入口 http://127.0.0.1:4195/ 。皮肤列表复用 configs/skin-review.json，图集与部件来自当前模板，维护源仍是各皮肤的 assembly.json。build校验现有配置及原图摘要后生成独立静态快照；没有写入API或模型服务。

## 操作

1. 选择皮肤、图集、部件。原图框显示稳定assetId；拖框移动，拖右下角缩放，或填写原图像素坐标后点击应用参数。
2. 核对组包后部件上的切线、内容边距和目标尺寸渲染。密度沿用组包含义；切片、边距与最小尺寸遵循正式Schema的整数逻辑单位。
3. 自动切线直接复用panel-slicer建议函数；点击分析不会改变配置。点击采用才将建议向上取整到整数逻辑单位并做合法性检查；若最小尺寸不满足，拒绝修改，需要人工核对而非自动放宽。
4. 垂直滑轨/滑块可配置原图像素单位的上下端帽，仅伸缩中段；其余部件继续沿用等比装框和状态组共享尺寸规则。
5. 源图替换是对当前文件的替换，会同步更新所有引用该文件的部件摘要。新图须容纳现有裁切框；该版本不自动识别新位置、调整坐标或判定缺件。新路径为inputs/摘要前缀.png，使用“下载当前源图”保留原字节。
6. 支持撤销/重做、JSON导入与导出。导入要求当前皮肤、模板、部件及源图摘要匹配。刷新页面会丢失未导出草稿；切换皮肤则各自保留本页草稿。

## 回到正式流程

下载的assembly.json仍是唯一组装维护格式，没有引入工作台专用配置。保存到所选皮肤工作目录或单独候选目录，保留其中所有相对源图路径；新图放入inputs子目录。不要移动配置却遗漏源图。

```powershell
npm run skins:postprocess -- inspect --config work/skins/<皮肤>/assembly.json
npm run skins:postprocess -- build --config work/skins/<皮肤>/assembly.json
```

页面不直接写入仓库、组包或发布。已验收的4194组件快照不会随草稿改变。后续如需展示修改结果，按既有流程构建并重新验收；不要改生成清单。

## 实现与验证边界

- src/skins/raster.mjs 是Node和浏览器共用的裁切及预乘alpha面积重采样，src/skins/assemble.mjs 是共用组装适配。旧PNG/normalization入口保留兼容导出，无第二份算法。
- 构建时用正式PNG解码器准备RGBA数据；69项浏览器检查中60项逐部件比较组装后的字节摘要，覆盖两套皮肤所有部件。其余覆盖越界拒绝、撤销重做、JSON往返、建议不自动修改、拖动、源图替换和原字节下载、非法端帽拒绝。
- 新上传PNG的浏览器预览使用浏览器解码，可能存在低alpha颜色取整；原始PNG字节及摘要保留，正式组包由CLI重新解码并验证。页面展示不代替最终PNG质量验收。
- 实际尺寸预览复用panel-slicer的SlicedBackground和几何实现；等比部件使用Sprite保持比例。不是面板布局编辑器。
- 当前还没有未知图集自动定位、从零创建风格、新增部件合同编辑、自动处理无法容纳旧坐标的新图或浏览器一键写回/发布。

浏览器回归：`node scripts/asset-workbench-check.mjs`，证据保存在当前构建的evidence目录。服务按摘要读取构建快照，新构建需重启服务。
