# Reference preparation: 固定样本验收

本表冻结 8 张跨风格角色和 5 个历史问题对照，供以后修改 `prepare` 时比较。
它们已参与观察、诊断和局部修正，是**已见回归集，不是未见盲测集**。
每种风格仅一张图，角色、背景也不同，不能计算泛用风格成功率。

这是 v0.3 以前本地 ONNX 路线的历史验收基线，不代表当前 fal.ai
BiRefNet V2 路线已通过这些真实图片。当前路线直接采用 provider 的精修 RGBA 前景，
只保留轻量校验、透明 RGB 清零、拟合、预览和指纹；像素可能变化，必须另行受控重跑并人工比较。
`correct` 是独立的可选人工确认路径，不是默认分割已经学会了补洞。

## 三类证据不要混用

| 证据 | 可以证明 | 不能证明 |
| --- | --- | --- |
| 公开合成 fixture / test double | 已知输入的 alpha、区域边界、摘要、状态和错误处理契约 | 真实模型分割准确率 |
| 真实图片的结构校验、文件指纹 | 输入输出身份、报告完整性、结果可追溯 | 衣服没有误删、每根发丝正确、物理 alpha 正确 |
| 人工看图与问题区域测量 | 所看区域的具体残留或丢失；是否值得继续使用 | 全图像素真值、统计准确率、所有相似风格都适用 |

下面的视觉判断来自此前 Agent 的逐图观察；不是程序自动得出的质量通过，
也不是用户对整批图的批准。机器人局部修正另有明确用户批准，单独记录。
本批 8 例默认 `prepare` 的报告结构均通过，警告为空；这与仍有视觉失败并不矛盾。

### 06 的已批准局部修正版

用户批准后，程序已把该预览应用成新的 v5 preparation。原图、默认结果和旧计划
均保留。原 cutout 坐标的矩形为 `[568,92,600,128)`，背景采样点为 `(582,108)`。
共 294 个像素改变，矩形外 RGBA 完全相同，主体拟合框和比例未变。

孔内大片洋红残底得到清除，但不能据此宣称所有暗色边缘混合都已精确还原。
这是 `user_confirmed_local_correction_not_default_prepare`，**默认分割行为没有变**。
获批预览摘要、修正版文件摘要和准备报告摘要都单列在清单的 `followups`，不覆写
baseline。详见 [局部修正流程](reference-correction.md)。后续视频仍需新计划与计算确认。

## 5 个历史对照

| 清单 ID | 已观察事实 | 修改后的验收要求 |
| --- | --- | --- |
| `old-03-white-outfit-holes` | 原 PNG 白衣主体及所看孔洞基本可用 | 不误删白肩、白衣、白靴；孔洞仍需透明 |
| `old-02-long-hair-tail` | 原 PNG 长发狐尾主体基本可用，部分孔洞仍有低 alpha 残留 | 看原尺寸发隙；保留发束，不能只看512总览 |
| `white-jpeg-75` | **未解决：白鞋面误删**。与 PNG 对照相同坐标，alpha 从254/254变为5/26 | 不把 JPEG 判成非法输入；不以重存 PNG、全白补满或镜像推理宣称修好 |
| `new-03-feathers-flyaways-openwork` | **未解决：细发/羽毛黑底亮边** | 不牺牲细梢换干净缩略图 |
| `new-06-translucent-gauze` | **未解决：大片薄纱遗漏** | 不能把缺失材质当透明成功，不自动进入视频生成；局部去底不能补回 |

历史 PNG、JPEG 是同一角色的关联对照，不是独立新样本。原图重新合成紫底、缩放、
镜像或重编码的结果也不能被计作新角色或 alpha 真值。已拒绝的“自动清理闭合孔”
候选曾删除猫鼻、蘑菇眼睛高光及合成同色前景，**没有接入默认链路**；不能为了修孔
再次引入全局同色删除。已批准的显式小区域操作也仍需人工查看区域内是否有前景。

## 公开契约回归与真实验收的分工

| 公开测试 | 受控契约 | 局限 |
| --- | --- | --- |
| [输入边界](../tests/test_preparation_boundaries.py)＋[fixture](../tests/fixtures/golden/reference-alpha-boundary-cases.json) | 有效贴边 RGBA、软 alpha 保留；小透明孔不冒充已分割；有界 I/O 恢复不重跑推理、不覆盖目标 | Windows 故障分支含 test double，不证明所有系统实测通过 |
| [参考图 matte](../tests/test_reference_matte.py)＋[fixture](../tests/fixtures/golden/reference-matte-cases.json) | 已知 mask 下白衣保留、背景洞和去混色、不偷偷修补错误语义 | 不保证真实模型给出正确 mask |
| [半透明材质](../tests/test_reference_translucency.py)＋[fixture](../tests/fixtures/golden/reference-translucency-cases.json) | 已有真 alpha 的保留与重合成；遗漏材质不能伪造恢复 | 不意味着真实薄纱分割已解决 |
| [局部修正](../tests/test_reference_correction.py)＋[fixture](../tests/fixtures/golden/reference-local-correction-cases.json) | 预览/应用分离、准确摘要、区域外不变、同色前景对照、篡改拒绝、来源链、新目录发布 | 不证明 Agent 选区正确或用户真的看过图 |
| [入口和清单](../tests/test_reference_discovery.py) | Skill 命令与 CLI 一致、示例可解析、清单格式和源码分发成员完整 | 不执行真实分割，不证明自然语言 Agent 行为必然正确 |

任何 matte 修改应先通过这些无模型回归，再在另行获准的 provider 验收中重跑
同指纹真实输入。新结果写新目录，记录新源码/包和固定 provider profile；旧失败保留。
新增算法若修好一例却损伤白衣、高光或薄纱，不能以单例改善放行。

## 验收与后续样本规则

- **可继续规划：**主体与所需细节经目视认可，结构通过；这仍不批准视频计算。
- **需要复核：**细线亮边、低分辨率、材质与背景近色。看原尺寸及目标背景，不靠空警告放行。
- **当前不接受：**明显残底、主体丢失、薄纱大片遗漏。可请求更合适素材；不能一概要求透明图。
  可识别的小残底才考虑先预览、后批准的局部修正；不自动改参数或模型反复试到“成功”。
- `strict` 与 `best_effort` 都不允许把错误 alpha 或缺失主体说成透明质量合格。
  `best_effort` 不是忽略看图缺陷的开关；交付允许省略什么见
  [质量策略](../../video-sequence-harness/character/docs/quality-policies.md)。
- 下一批若用于评估泛化，应预先冻结未见角色、尺寸、背景、验收区域和判据；模型参数与
  后处理固定后再看结果。用于诊断或调参的样本转为已见回归集，不能继续充当盲测成绩。
  新原画生成、真实 provider 分割或视频生成按各自权限另行批准；CI 不承担这些计算。

## 指纹与复现边界

### 后续 JPEG 输入视图的范围与取舍

历史表格保留当时的基线结论，不用后续候选覆盖旧失败。另一次固定8份已见JPEG
对照中，主模型输入的MedianFilter(3)副本改善了白衣右脚；同时雪貂几根胡须
明显变淡或缺失。其余观察为5份未见明显变化、1份枪刃小孔材质仍需复核。
其中6份对照原图双模型链，另2份仅对照历史单模型去噪结果，分母不能混为泛化成绩。

用户明确表示这次白鞋完整更重要，雪貂所示胡须损失可以接受；这个取舍仅适用于
已展示的变化，不代表用户确认了全8份，也不代表其他细线装备、材质或主体误删
都可以放行。没有alpha真值，不报告像素准确率。主模型视图中的一像素细线可能
丢失，新增公开fixture会如实验证这项信息损失，不把它算成“质量改善”。

[JPEG输入契约测试](../tests/test_reference_input_view.py)与
[合成fixture](../tests/fixtures/golden/reference-jpeg-input-view-cases.json)覆盖格式识别、
EXIF方向、原图保留、主/辅/RGB分路、alpha和报告完整性。只使用test double，
不在CI执行真实分割。JPEG v7行为和兼容性详见[prepare说明](reference-preparation.md)。
如果某个需求要求完整保留胡须、细线或其他配件，仍应单独看图判断，不沿用本例接受意见。

[reference-acceptance-v1.json](reference-acceptance-v1.json) 只发布允许公开的 SHA-256、
字节数、样本 ID、观察分类和合成测试路径，不含原画、模型文件、主机/服务路径或私有配置。
`report_file.sha256` 是报告文件字节摘要，`preparation_sha256` 是程序的规范化文档摘要，
两者用途不同。风格组还绑定35个运行文件的规范化清单摘要；历史组绑定当时的本地 WIP wheel。

这些结果来自**未发布 WIP**，尽管工具字段当时仍为0.3.2，也不能归属于已发布 v0.3.2。
清单不内嵌完整运行快照或原画，因此外部使用者仅靠它不能重跑这些真实图片；它是
可追溯索引，不是自足的真实 golden 数据集。公开 CI 可重跑的是上表合成 fixture。
真实样本及原报告保留在本地忽略目录，后续若要公开，需另行确认素材分发权限并单独打包。

Windows 本地测试、CI 配置存在、真实跨平台执行和干净安装验证是不同证据。
发布前仍需从实际 wheel/sdist/Skill 包进行干净安装与支持平台验证；本次文档冻结不代替该门禁。
