# 规划归属与内部几何

alpha.9 修正官方 `host-run` 的预算提示：合板只决定请求分组，不能要求把卡框、
可替换内容和状态强制合为一张。基础规划合同仍区分可替换内容槽、固定构图插画和
固定读数卡；完整固定插画、固定附饰不会因此自动拆开。

## 已确认的问题

alpha.8 的一份装备商店真实样本完成了 M1/M2、9 次生图和一次独立整图复审，
24/24 个素材身份都已导出，但整图复审报告 7 项视觉差异：外框加粗叠加、徽饰
位置和遮挡、商品与金币放大、按钮重叠，以及配色变化。素材数量齐全与包校验
通过都不能证明视觉还原通过。

审计发现，M1 动态预算段要求卡片内部插画、卡框和图标同属一张完整素材，覆盖了
基础规划合同对可替换内容槽的拆分规则。已有 `planning_capacity.estimate` 本来只
核算分组和调用数，不改归属；本次使模型提示与这项程序职责一致。

程序只能对一份素材整体缩放、平移，或按已许可的 frame 合同适配可伸缩表面。
如果生图已经改变整卡内部的商品大小、金币位置或描边厚度，外框归位无法独立
纠正这些局部。不能根据辅助框直接裁剪、缩小真实图形或伪造内容修复。

## 新任务行为

- M1 先按基础合同确定唯一归属，再核算调用预算。可替换刚性内容使用 uniform，
  独立的可伸缩底板才可使用 frame；不为了节省调用强制合并。
- M1/M2 显式检查内嵌刚性图形定位、文字留白、边框厚薄、突出附饰与另属控件的
  真实间隙。AABB 交叉不是 alpha 遮挡证明。用户通过已有 `planningNotes` 提供
  实际整卡比例或轮廓失败证据时，按基础合同复查拆分；程序不自动修改归属。
- 一次最终 `composite_review` 的 `dispatch.json.materials` 增加 `ownedObjects`
  （objectId、kind、referenceBoxNorm、appearance）和 `registrationMode`。
  数据来自实际冻结候选，随 dispatch、请求和 scope 摘要绑定；缺少辅助框保持 null。
  这些是原计划定位提示，不是生成图主体观察或已测量 alpha。复审仍比较实际候选图。

没有新增 stage、配置、授权类型或默认模型调用。正常路径仍是独立 M1/M2、
v13、sheets、最多三路持续补位、原生透明度和一次最终整图复审；逐素材及主体
模型调用仍为零。生图提示、参考裁片合板及 board v6 的纹理来源绑定保持原样。
素材和请求数由新 M1 后的程序报告，不能假定旧样本的 24 素材、9 请求仍适用。

## 验证与升级

新增离线回归覆盖：独立刚性内容经过预算核算后仍保留身份与原 M1 字节、M2 前
不触发生图、整卡外框对齐却存在内部放大、独立刚性图形无拉伸归位、单次最终
复审绑定实际内部定位与候选，以及定位提示篡改阻断。既有固定整卡和默认预算
回归继续适用。合成 fixture 不代表真实模型遵循了新规划提示。

本修订尚未做新的真实模型验收，不能声称旧样本的 7 项差异已消失。下一次验证
须新建任务、使用新版不可变安装，先单独确认规划预算，程序核算后再确认生图与
一次整图复审预算。未知结果不重发；旧运行目录、快照、授权、回执和交付包不变。
消费端透传整个最终复审 packet，不能剥离内部定位字段或据此生成额外观察调用。
Docker 服务接入无需新增阶段；本修订不操作 Docker。
