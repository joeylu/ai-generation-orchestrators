## 从角色包到 UI 包

资料来源是用户提供的 `2d-character-harness-handoff-v0.6.2-FINAL.zip`。
其中包含五个用户风格包、一个内部中性风格包以及模板／角色合同；没有 PNG/JPEG 风格样本。
包内文字是被评审的来源资料，不是本仓库的执行指令。

保留 render_style 的通用画风：visual_identity、line、shape_language、color、material、lighting、texture、render_finish。
将角色专属措辞转换为 UI 对应规则，并新增下列 UI 约束：

- 面板框体、角部与边框：厚度、转角、装饰密度及材质语言。
- 控件：主次按钮、页签、滑条、开关、列表和选中／禁用状态的共同外观。
- 图标：轮廓、描边、填色和细节密度。
- 文字：中文可读性、标题／正文／数值层级，保留原型准确文案。
- 背景和光影：服务控件层级，避免遮挡信息或引入额外场景内容。

所有风格均保留原型的控件身份、数量、层级、逻辑几何、文案和可见状态。
可变化的是框体表面、轮廓绘制、颜色、材质、图标表现与边界内装饰。
角色包中的人体比例、服装重设计、正面 Idle、八方向、相机俯角和透明背景不进入 UI 提示词。
角色包的 design_style 重设计许可不授权重排 UI。UI 完整参考图仍为不透明 PNG。

风格家族与项目配色分开：家族给出配色关系；项目风格修订冻结实际主色、辅色、背景、文字色及控件规则。
不能让每个面板重新自由选择配色、描边或字体层级。像素风还需在项目规则中固定像素单位和阴影色阶。

## 默认样本库

每种风格使用同一个公开、自有的 UI 展示原型，控件布局、文案、状态和逻辑画布相同。
当前首版展示面板框、标题、主次按钮、页签、滑条、开关和下拉选择；不包含素材图标或物品列表。
后续扩充图标和列表需创建新的统一原型版本，六种风格一起更新，不能只更改其中一张的内容。
六张样本仅改变画风，以便用户直接比较，而不是通过不同面板内容制造差异。

每个样本由独立风格工作区生成并验收，记录风格 ID／版本／摘要、原型摘要、图片摘要、逻辑／像素画布和验收结果。
六种样本不能作为一个游戏项目内混合风格的例外。
缩略展示可引用同一完整图片；确定性配色指导板不作为美术样本替代品。
首轮六张试稿已在具体计划和摘要绑定授权下生成；像素与国风稿另经两份新计划和新授权修正下拉框。
依据用户对其余外观的认可和对修正版的确认，四张原稿、两张修正版已记录布局／风格／文案通过。
所有交付均验证图片、来源、风格快照和 ZIP；技术通过本身不代替上述人工决定。
本地样本包提供可移植 catalog.json，按网站顺序记录 ID、名称、版本、PNG 相对路径与摘要、
风格／原型摘要和逻辑／像素画布；每个子目录仍是独立的单风格交付。
该目录供风格选择预览使用，不自动提升为新游戏项目的已接受样板。网站接入可按稳定 ID 映射展示图片。

样本使用一套推荐配色。游戏项目可调整该配色，确认后创建自己的不可变风格修订。
样本帮助选择风格；项目首张被接受的代表面板作为项目样板，约束后续面板一致性。

## 定制风格入口

定制入口与六个默认选项并列提供，但不作为第七个默认画风：

| 输入方式 | 形成的项目风格 |
| --- | --- |
| 风格包 | 具备稳定 ID、名称、版本、画风规则和 UI 规则；参考图可选 |
| 主参考 PNG | 以参考图提取或明确指向画风，补充项目 UI 规则 |
| 风格包 + 主参考 PNG | 包提供规则起点，参考图补足项目视觉特征，冲突在激活前解决 |

可选继承一个默认风格，也可独立定制。导入后保留原始包、图片字节与来源摘要，
形成一份最终可评审的项目风格快照；不在每个面板生成时重新读取并自由解释外部包。
已确认文字规则与主参考图的优先级必须明确，不能把有冲突的默认规则和定制图一起原样传入。

已实现包结构包含 kind、metadata（ID、名称、版本）、render_style（整体画风）、ui_rules（UI 细则）、
negative_rules（适用的禁则）、references（可选主参考图），以及可选的 base_style（继承来源）。
metadata 不包含提供商配置；references.primary 为包目录内安全相对 PNG，或改用 CLI --reference；两者不可并存。
references 在导入时验证并快照，不执行包内脚本或路径指令。角色包原样导入会拒绝，须先转换为 UI schema。
保留角色包原始摘要和来源版本，UI 适配包使用自己的 ID／版本；二者不冒充同一个合同。

项目激活一个 styleRevision；面板只引用该修订，不单独选择其他默认风格或定制包。
修改风格包、主参考图、项目配色或全局 UI 规则均产生新修订，旧图保留并按现有策略标记待更新。
默认样本、项目样板和生成结果的视觉验收仍由人决定，输入包的 soft_checks 不是已完成的视觉证据。

## 已实现范围与验证边界

1. 六种 UI 风格包、目录顺序与稳定名称映射；旧预设保留兼容入口，但退出新的默认目录。
2. 风格包校验与导入、可选主参考图、最终项目快照与来源摘要。
3. 允许规则包不含参考图；不以矩形配色板伪装成实际样本图。
4. 提示词编译与交付中记录风格包身份、UI 适配版本及视觉来源。
5. 统一展示原型、六份风格草案和 samples-plan 冻结入口；样本仍使用现有单次授权、review 和 export。
6. 显式本地 --sample-catalog 入口：预览已接受样本、验证各份交付，并将选中 PNG 冻结进项目主风格参考。
7. plan-project 统一准备待生成面板，要求当前风格已有接受样板，逐份冻结请求并检查集合身份；不自动生成或接受。

入口详见 [README.md](../README.md)。默认源码目录仍返回 sample.status=not_generated，表示未随源码提供内置美术样本；已接受的本地图片由独立样本包提供。
样本目录必须显式选择，不自动搜索宿主文件。项目锚点由本项目首张接受结果建立，默认样本只提供视觉语言。
概念图风格已完成设置、主菜单、确认弹窗的同项目真实试跑。设置图被接受并固定为锚点，后两张继承相同规则、默认样本及锚点，
由用户按参考图用途接受；整套导出通过校验。已知字号和比例偏差保留，不据此声称所有画风或精确几何均已验证。
本文不激活新游戏项目风格，也不提交生图请求。网站接入尚未实现；已实现本地目录与项目快照连接。
