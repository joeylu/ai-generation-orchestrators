# 本地 UI Studio

2026-10-14。当前实现与验收状态以本文和执行文档 12.91–12.100 为准；早期分步记录保留在 execution-plan.md。

## 启动与使用

在本 Harness 目录执行 `node scripts/studio.mjs work/studio/project.json 4210`，打开 `http://127.0.0.1:4210/#library`。只监听本机。当前 UX 实现与验收见执行文档 12.91。

1. **组件项目库 → 新建组件项目**：填写名称，选择六种带图预设之一，或上传 PNG/JPEG（最大 8 MB）；可选补充描述。预设图与生成输入校验同一摘要。
2. **生成组件库**：先保存冻结计划，再确认本次四张图的模型调用。同一批次最多两张同时生成，每完成一张补入下一张，每张仍只调用一次。取消不生成，项目仍保存在库中。初版自定义需要参考图，不提供纯文字自动生成参考图。
3. **制作进度**：显示保存风格、生成图集、拆分与检查、组件入库四个阶段；每张图集独立显示状态和有记录的耗时，返回后可放大。收齐后自动进行本地定位、拆分、组包和检查，并显示已完成步骤数量。退出页面不取消已提交任务。收到原图不等于完成，原始检查偏差仍保留。
4. **组件画布**：从可预览项目进入，查看/试玩16类组件。左侧列表定位，空白处滚轮缩放，空格/中键/平移工具移动视图；组件内部优先处理其交互。Dialog 点击确认会按配置关闭，原位置显示“重新打开”；再次点击左侧 T11 Dialog 也会定位并打开。只恢复该弹窗，保留其他控件状态。相机和试玩状态不写回导出默认值。
5. **面板生成台**：选择 ui-reference 五类八状态预设，或输入自定义需求，选择已完成的组件项目，在网页确认一次面板模型调用。组件版本冻结；显示理解需求与组装、生成横竖预览、整理交付文件三个阶段，交付两种方向，按所选方向优先打开。
6. **面板作品库**：查看面板结果、需求及组件版本，预览并下载。失败、需补充需求和待确认结果均保留。

失败项目从卡片“继续制作”进入；图集结果不明时可零调用检查恢复，仅补缺图需要新的单次确认。已启用自动处理的项目在 Studio 重启后可从已校验步骤继续；暂时性本地错误有次数上限，质量、证据和工具版本问题仍停止并显示原因。未启用自动处理的旧项目不加入自动恢复，已有完成包不重建。详见 [本地自动恢复](local-recovery.md)。

更多操作：创建页可导出输入草稿，左下“本地文件”可导入；旧示例保存在“早期示例与产物”。真实项目与产物不会被本轮界面迁移覆盖。

Tabs 内容区默认使用皮肤的 `surface.content` 底板并保留安全留白，页面文字按底板取包内字色。ScrollView、Dialog、Panel 已有底板；List 保留逐条皮肤，Text/Image/Container 和选择控件组保持透明。完整审计见执行文档 12.107。

共用组件运行时更新后，新项目自动采用新实现。已有完成项目由维护命令 `node scripts/studio-upgrade-components.mjs --project work/studio/projects/<UUID>` 显式更新：复用原皮肤生成并检查新的消费包，通过后切换画布和下载引用；不生图、不重切、不覆盖旧包。运行时选择证据保存在 `work/component-upgrades/`，由 `src/studio/component-upgrade.mjs` 核验，flow.componentRuntime 仅保存经过程序验证的引用，不应手填或修改生成清单。需要重启旧 Studio 进程才能加载新增的选择逻辑；重启前确认没有进行中的任务。新包仍为待外观验收候选，旧面板保留冻结版本。

## 维护位置

| 内容 | 位置 | 责任 |
| --- | --- | --- |
| 模板与组件结构 | configs 中既有合同 | 数量、尺寸、状态和绑定 |
| Studio 缺省样式 | configs/studio-metadata-profile.json | 字体、间距、滚动条等；通用几何基线；新项目文字亮暗由源图采样并记录证据 |
| 预设风格 | configs/studio-styles.json + assets/studio-styles | 名称、版本、图片摘要、允许移植的风格规则与色板 |
| 自动本地处理记录 | 项目目录 auto-process.json + flow.json.localRecovery | 绑定批次、持久次数、失败原因；重启可安全继续 |
| 本地恢复策略 | configs/local-recovery-policy.json | 最多 3 次自动启动、重试/等待间隔；模型不自动重投 |
| 图集并发策略 | configs/skin-generation-execution.json | Studio 与 Codex CLI 共用，maxConcurrentSheets 默认 2，可设为 1；重启后生效，不打断已运行批次 |
| 网页确认 | src/studio/confirm-ui.mjs | 统一文案结构、键盘焦点、取消与确认；提交仍由对应流程绑定原计划 |
| 真实进度展示 | src/studio/progress.mjs + progress-ui.mjs | 状态映射、步骤数量、时间显示；不改写任务证据 |
| 文字主题证据 | 项目目录 theme-evidence-*.json | 源图采样与输出 profile 摘要 |
| 默认展示产物 | work/studio/project.json | 本机登记，不是发布清单 |
| 项目输入和四板计划 | work/studio/projects/UUID | 快照、原图、批次摘要 |
| 项目流程索引 | 同目录 flow.json | 关联任务和面板，不替代原生回执 |
| 运行证据 | work/skin-codex-relay、skin-tasks、panels/model-runs | 对应执行器生成，不能人工改写成功状态 |
| 验收结果 | work/studio | 回归、浏览器、真实流程记录 |

主持层只关联和调用，不复制生成、切图或布局业务。重启时未完成的面板调用显示中断，同一计划禁止重投。工具变化时使用相同原图新建确定性任务，不再生图。ZIP 只包含校验过的产物，附带原生 manifest/report；不包含项目输入、模型会话或授权文件。

## 边界

- 本地 Studio，不包含 Docker、远程部署、账号、数据库、队列或多人协作。
- 16 类组件可预览；AI 转换支持五类八状态预设和受限自定义混合控件，能力边界见自定义面板文档，不宣称任意组合都已支持。
- 文字属性和局部画布编辑后置；现阶段通过需求生成候选，导出创作 JSON。
- 新自动项目已接通可追溯的主面板亮度采样与文字亮暗选择；这不是完整视觉分析，混合深浅控件仍需外观检查，旧包主题不改写。
- 程序检查不代表美术接受或生产发布。原生 productionReady / visualAcceptance 保持候选语义。
- 视觉复核仍保留；未来部署若需要模型复核，应接正式 session 接口。

## 界面与验证

固定侧栏、浅色工作区、绿色主操作；默认折叠路径、摘要和执行细节。提供禁用态、键盘焦点、状态提示和窄屏单栏。系统中文字体，无外部字体或 CDN。设计参考 ui-ux-pro-max 的简洁工作台与可访问性规则。

`node --test tests/*.test.mjs` 运行离线回归；`node scripts/studio-check.mjs` 运行使用模型替身的浏览器检查，不消费额度。

真实验收单独执行，要求明确授权，不加入自动测试。`studio-real-acceptance.mjs --real-confirmed` 在已有验收记录时拒绝重投。后续脚本只续接已有项目。实际结果见执行文档 12.86 和 work/studio 记录。


### 生成结束但缺少图集

在历史计划中点击“检查并恢复已返回图片（不生成）”。程序只核验已保存的原图和调用证据，成功后显示“已恢复接收”，不会重新调用模型。没有可核验图片时保留原记录并说明原因。恢复接收不代表尺寸、部件位置或外观已通过。

维护入口：`node scripts/recover-codex-sheet.mjs --project <项目目录> --batch <批次摘要> --sheet S04`。可选 `--relay-root` 和 `--codex-home` 指定本地证据根目录。已有失败、收图和质量记录均保留，恢复不允许替换已接收图片。


### 只补缺失的一张图集

打开“历史计划”，展开项目，点击“仅补生成 S02”（或对应缺失板）。程序先准备新计划，弹窗说明只调用这一张；确认后才调用真实模型。取消保留待确认计划，不消耗生成额度。收到后复用原来的其他三张，进入“当前项目”继续拆分组件。失败记录仍保留，不会自动重试，也不会允许替换已接收的图集。


## 新 UX 离线回归

运行 `node scripts/studio-check.mjs 4212` 会启动临时回环夹具，在已安装 Edge 中验证操作后退出；所有生成/拆分/面板操作为内存替身，真实模型调用为 0，不写真实项目。需要既有 work/studio/project.json 中可校验的预览资产。运行中的正式 Studio 仍使用 4210，二者不混用。浏览器报告见 work/studio/ux-browser-check.json；最新验收数量和证据见执行文档 12.97。可传第三个参数指定仓库外截图路径。

面板预设现与 ui-reference 统一为五类八状态：开始、设置、暂停（在线／本地）、结算（完成／失败）、加载（加载中／失败）。先选类别和状态，再选组件项目；补充需求可留空。程序固定预设来源与组件版本，生成横竖两版。仅支持所选结构内文案／初始值定制；参考几何和装饰不保证逐像素一致。维护入口为 `src/panel/reference-presets.mjs`，八套内容源保留在 ui-reference，不在 Studio 再维护一份。历史确认／表单作品仍可打开。

组件检视画布使用黑色 28% 不透明度展示底板。文字按实际皮肤底色自动选取对比色；这是预览辅助，状态栏会提示，导出仍保留原包的主题字色。策略维护在 `src/studio/canvas-contrast.mjs`，不覆盖历史资产。

正式文字机制见 [文字可读性](text-readability.md)。新包的角色字色在打包阶段确定，组件画布、独立消费及面板共用；画布显示需复核状态数量与检查报告入口。上文的预览辅助策略仅保留给旧包。

画布逻辑尺寸固定为 1440×1120，CSS 显示尺寸与像素缓冲区分开。缩放时按 `屏幕 DPR × 相机倍率` 提高 Pixi 渲染分辨率，并通过 renderer.resize 的分辨率参数使文字纹理重新栅格化；平移不重新分配缓冲区，缩小释放多余像素。策略唯一维护在 `src/studio/canvas-resolution.mjs`：分辨率按 0.25 向上分档，受 GPU 最大边长、8192 像素边长和 32 Mi 像素总预算约束。超过预算时保持有界清晰度，不无限增加显存；PNG 皮肤细节仍受原始素材分辨率限制。此设置只影响 Studio 检视，不修改组件包、字体大小、九宫格、导出尺寸或试玩状态。新旧组件项目都使用同一预览策略。

创建方式新增“自定义面板”，需求必填，可与原八套预设切换并保留已输入文案。当前支持八类内容/控件组合、单列与滚动，具体能力与维护入口见 [自定义面板](custom-panel.md)。

## 网页确认与进度含义

面板作品库每张卡片提供“删除面板”，确认后移入回收站；顶部“查看”筛选切到回收站后可恢复。删除后也从生成台隐藏，不删除组件项目或磁盘文件；历史生成记录保留。运行中的面板不能删除，恢复不会重新调用模型。当前不提供永久删除和磁盘清理。

新建面板必须先选择“画布比例”：横版 16:9 或竖版 9:16。这个选择固定进计划和消费者配置，生成、预览及下载只包含选中方向；模型仅解释面板内容，不负责选择比例。旧双版产物保持原样。补充任务沿用已选比例；无比例记录的早期任务须先选择再提交补充。

面板生成台顶部用于创建新面板。已有任务显示“需要补充需求”时，点击该任务内“补充需求”，在独立“补充回答”框中回答问题，然后“保存补充并继续”。原需求、问题、组件版本与类型一起进入下一版计划；任务 ID 不变，历史计划与结果保留。确认后才调用一次模型；取消后保留待确认版本，刷新后可继续确认。输入中的回答不会被轮询清空，但未保存草稿不跨整页刷新。之前误建的独立任务不会自动删除或合并。

整批生成、单张补图、面板生成和覆盖未保存草稿统一使用网页内确认面板；生成确认显示本次调用范围、选用组件版本或图集，计划摘要折叠在“查看计划标识”。取消、Esc 或切换页面不提交，轮询更新不会关闭确认面板，重复点击不增加调用。关闭含未保存内容的浏览器页面仍保留标准离页保护。

服务重启造成任务标识变化时，项目轮询会重新绑定补图控件并取消对应旧确认；旧票据不会重用。若点击恰好先于轮询，界面提示状态过期并刷新，需要重新点击操作和确认。准备失败会恢复按钮并显示原因，不把未提交请求显示为持续生成。

图集接收 `N / 4` 表示已核验接收的原图数量；本地 `N / 5` 是通过的步骤组（核对原图、定位、拆分与切线、安全区、组包与检查）。DAG 新增组会额外展示，不会被旧的五步定义隐藏。项目库卡片同步展示数量，制作页显示单张等待提交、生成中、已收到、失败或结果待确认。

模型未提供生成百分比，界面仅显示已提交、等待返回和真实已用时间，不推算剩余时长。接收数和本地步骤数不能视作等耗时的总百分比。结束耗时固定，历史缺少时间戳时不补造。失败与结果不明保留处理说明，不持续伪装“生成中”，也不自动重投。

缺图的终态会读取当前计划对应的本地调用证据，在卡片显示「模型连接失败」「生图连接失败」「未返回图片」或「有图片待核验」等说明。此诊断是只读展示，不改写原结果，不触发生成或恢复。匹配的工具/协议结束事件可用于停止耗时显示；缺少证据时保留通用提示。维护入口为 `src/skin-generation/codex-diagnostics.mjs`，原始日志不发送给浏览器。

若已进行过多次补图，诊断和恢复会沿经过核验的同一 replacement 链查找历史原图；显示「历史图片待核验」时优先使用恢复按钮。图片成功后 CLI 收尾连接失败的情况，也必须通过完整工具和字节审计才能恢复。补图恢复会附加来源记录，不把最新失败调用改写为生成成功；收图卡片显示「已恢复接收」。发现已核验可恢复图片时，新的补图准备会被阻止，以免重复生成。维护入口为 `src/skin-generation/codex-recovery.mjs`、`supplement-recovery.mjs` 和 `supplement-intake.mjs`。

遇到连接失败，先暂停连续补图，检查网络或代理，稍后仅补缺失的一张。CLI 预检通过只表示本地登录与配置可用，不能保证下一次生图连接成功；重新提交仍使用新计划和网页明确确认。已有图片待核验时优先点击「检查并恢复已返回图片（不生成）」。

面板生成提交后，在当前页面等待会于交付检查通过后自动打开面板预览；刷新同一标签页仍保留等待。中途离开页面、切换组件或编辑新需求时仅提示完成，可从面板作品库打开。失败或需要补充需求时不会跳转；返回作品库不会再次自动打开旧面板。

面板作品库中，已完成面板可点“选择动效”。预览顶部提供原样、轻快、精致、稳重四个选项，选择即保存并播放，也可重播入场；刷新后保留。本版覆盖整体入场、按钮及通用控件反馈。无需重新生成，不消耗模型额度；动效配置单独导出，原始交付包不变。系统启用减少动态效果时保留选择但不播放。

组件项目库 → 打开全局组件画布：顶部“全部组件动效”统一选择原样、轻快、精致或稳重，“重播全部入场”覆盖 16 类组件。选择按本项目及皮肤版本保存，刷新后恢复；可独立导出动效 JSON。组件画布动效与面板动效分别维护，选择不会修改已有面板，也不调用模型。所有类型有入场反馈，特殊控件内部过渡的覆盖边界与面板动效一致。

布局基础已升级为 PanelDocument 0.3：16 类组件共享弹性尺寸、最小/最大尺寸，Container 支持主轴对齐、固定列网格及子项内容自适应。新生成设置行和按钮组采用这些规则；旧作品和已打包组件保留原版本，不自动改写。普通 Studio 创建流程不新增一排布局参数；高级配置在独立画布编辑器的“尺寸与弹性”和 Container 排版区，或维护面板 JSON。具体字段、示例、旧包升级与当前边界见 [布局合同](layout-contract.md)。无需重新生图。
