# UI Reference Harness 0.7.3

发布标签：`ui-reference-harness-v0.7.3`。新增可选的 Codex CLI Code-mode 转发生图入口。

## 变化范围

`web/adapters/codex-cli-relay.mjs` 显式经 `functions.exec → image_gen.imagegen`
传递冻结参数 `transparent_background=false`，默认模型仍为 `gpt-6-luna / xhigh`。
原生 `codex-cli.mjs` 保持 0.7.2 严格参数合同，不向原生工具追加透明度字段。
宿主选择入口；同一任务提交后不自动切换入口或重新生成。

转发通过数据型 stdio MCP 一次读取确切参数，并在嵌套生图调用前后检查输入、会话身份和
单次凭据。只核对并在本次启动参数中信任适配器自己两份确切 Hook 定义，不改全局信任
设置，不使用信任或沙箱绕过开关。预检不启动模型回合。

正常结束的面板线程可持久恢复，每次修改仍冻结新计划；审计只读取本轮新增会话记录和
图片，拒绝覆盖历史输出。失败或结果不明时保留线程、原图和记录，不恢复提交、不自动
重试。核心 PNG 检查、编码规范化、人工验收、锚点和交付规则保持不变。

0.7.2 的已完成面板、风格预览和历史修改预算继续可检查、人工验收和交付。
旧冻结计算计划不可继续派发；新计算需要新计划和对应的明确决定。

## 安装和升级

固定本标签、完整提交、`ui-reference-harness-v0.7.3-source.zip` 的字节数和 SHA-256、
release-manifest.json 的 SHA-256 及 runtimeSha256，逐项验证 sourceFiles，保持原始字节和
三个兄弟 Harness 的目录关系。可选本地 Studio 使用配套同根目录的 studio ZIP。
Node.js 要求 >=22.18.0，推荐 24。

服务侧显式配置新适配器和持久私有目录，CLI 的 `CODEX_HOME` 必须与适配器定位原始会话
和图片时使用的目录一致。先运行只读预检，再按新授权验证实际生成；登录状态、可用工具
和信任结果须在实际宿主核对，不随源码包迁移。不得修改 vendor 或复制第二份核心。

升级前核对在途任务，保留旧运行时、工作区、session、原图与旧交付。转发入口的
`relay-sessions/` 与原生 `sessions/` 隔离，不导入旧线程映射，不重投历史失败或不明请求。
现有项目级 DAG 和 Studio UX 延续；本版不新增服务 API 或 Web 操作。
接入细节见 [宿主说明](host-integration.md#073-可选-cli-code-mode-转发)。

## 验证边界

离线回归覆盖严格参数转发、原图顺序和字节、跨进程单次保留、正常线程修改、不明状态
终止、缺失凭据、输出不唯一、实际模型替换拒绝及 0.7.2 结果兼容。
发布附件的 offline-regression.json 记录源码与解压包回归、逐文件检查及 loopback HTTP
检查，测试仅用合成夹具和提供商替身；发布过程真实模型调用为零。

本机此前已完成一次独立转发实验并由用户接受图片；正式适配器模块和 Docker 环境的
真实生成、多轮修改尚未验证。离线通过和安装成功不能代替实际图片的人工验收。
