# 组件内容区（body）审计

2026-10-16。状态：**源码审计与确定性修复完成，浏览器视觉待验**。本记录覆盖 16 类组件的内容所有权与边界检查职责，并记录本轮已复现的问题；不把源码审计视为真实绘制或视觉验收。

## 现场已确证的约束

本次冻结竖版面板的初始文档通过 `validateSizeEdit(base, base, ctx)`。`group-0-content` 是挂在 `group-0` 的 `content` 槽中的 Container 节点，不是缺失的资源。

| 项目 | 初始值 | 父分组减高 1 像素后 |
| --- | --- | --- |
| `group-0` Panel 设计尺寸与求解尺寸 | 490 × 255 | 490 × 254 |
| 表面层与内容边距 | `inset`；四边各 12 | 不变 |
| 父槽内偏移 | x = 12，y = 12 | 不变 |
| 父槽可用尺寸 | 466 × 231 | 466 × 230 |
| `group-0-content` 设计尺寸与求解尺寸 | 466 × 231 | 466 × 231 |
| 内容高度规则 | `heightMode: content` | 不变 |
| 结论 | 恰好容纳 | 内容高出安全区 1 像素，拒绝候选 |

内容自然高为分组标题 43、间距 12、进度区 116、间距 12、按钮区 48，合计 **231**；再加上下边距 24，当前这组内容需要父分组高 **255**。这是当前内容与皮肤的组合约束，不是所有 Panel 通用的最小高度。仅将该分组宽度从 490 改为 480 可以通过；减高才触发本例限制。

当前显式表面路径首先由 `validateDocument → assertSurfaceSlotChildren → surfaceSlotBox` 抛出 `panel.slot-bounds`，错误路径为 `group-0-content`；它早于编辑器后续的 `edit.slot-bounds` 检查。错误中的节点是放不下的子内容，拥有该安全槽的父节点是 `group-0`。反馈应同时说明两者，不能把节点名称当作额外文件名。

初始逻辑坐标链为：外面板 `surface` 位于 (50, 143.5)，自身内容偏移 (42, 42)；`custom-scroll` 位于 (92, 261.5)，其内容偏移 (14, 14)；`group-0` 位于 (106, 275.5)，安全槽及 `group-0-content` 起点为 (118, 287.5)。这些是初始滚动位置下的逻辑坐标，不包含编辑器相机缩放或平移。

外层 `surface` 初始为 620 × 993。保持宽度，将高度改为 992、900 或 250 都能通过：已有 ScrollView 缩小视口，内部内容仍可纵向滚动，不要求把三个任务分组一起压扁。改为高 200 时先触发 ScrollView 自身最小尺寸约束。不能仅因内容自然高度大于滚动视口，就判定 `group-0-content` 初始越界。

现场证据来自只读冻结预览提取及共享布局函数，记录文件为 `slot-constraints.json` 与 `slot-initial-inspection.json`。未观察浏览器，也未修改原文档、皮肤或生成产物。

## body 的含义与 16 类范围

`body`、`group-0-content` 等是 PanelDocument 内的节点 ID；节点通过 `slots` 引用组成树，不对应一个必须另建的 body 文件。组件适配器还可能创建内部文字、标记、列表或遮罩对象，这些运行时对象不等于可由作者挂载子节点的槽。

本轮区分 **6 类内容所有者**与 **10 类无作者子槽的组件**。前者需要校验作者子节点所占的空间；后者仍有文字、图形、九宫格与命中几何要求，不能因没有 body 槽就宣布所有几何已通过。

| 类型 | 作者子槽 / 所有权 | 本轮审计边界 |
| --- | --- | --- |
| Container | `children` | 由共享布局求解 flow、free、wrap、grid、padding 与实际子项矩形；可见性参与排版 |
| Panel | `content` | 按实际表面层、内容边距及标题预留计算内容区；普通内容不允许纵向越界 |
| Dialog | `content` | 扣除标题与操作按钮区域；legacy 与显式表面编译均允许纵向滚动，横向仍须容纳 |
| Tabs | `pages` | 页签栏、内容表面及安全内边距共同确定页面可用矩形，不能以整个 Tabs 外框代替页面区域 |
| ScrollView | `content` | 区分视口与自然内容；纵向滚动内容可高于视口，宽度仍受内边距及滚动条预留约束 |
| List | `items` | 行宽扣除内容层边距；显式行按自己的组件皮肤检查；普通 List 纵向裁切，未新增滚动能力；库存另用格位/详情几何 |
| Text | 无作者子槽 | 组件矩形与表面文字安全矩形分开；真实字体检查读取适配器实际 textBox，不再拿外框代替 |
| Button | 无作者子槽 | 各状态九宫格独立检查；文字使用所有状态每一边的最大 inset，与固定标签位置一致 |
| Switch | 无作者子槽 | 标签宽扣除双倍 markSize 与 labelGap；两种状态保留原命中矩形与字号行高 |
| CheckBox | 无作者子槽 | 标签扣除标记和间距；可见勾选图案越界时等比缩小到逻辑 body 内，透明边距不改变正常大小 |
| RadioGroup | 无作者子槽 | 初始化、resize、离线与真实字体检查统一扣除横排全部 gap；竖排保留原行高与间距 |
| Select | 无作者子槽 | 关闭面文字统一扣除双侧箭头预留；弹出列表视口限制在画布内，原选项和行高保留并可滚动 |
| Slider | 无作者子槽 | body 包含轨道、滑块和可选数值行；数值沿用独立字体检查与自身尺寸下限，未改其交互矩形 |
| ProgressBar | 无作者子槽 | 轨道与可选数值行保留各自高度、间距与居中规则；字号变更不缩放轨道 |
| Input | 无作者子槽 | 提示文字与原生输入按 field 的实际四边 inset；输入值仍可在控件内部横向滚动，不写回编辑文案 |
| Image | 无作者子槽 | 外框为组件逻辑矩形，纹理按既有 fit/position 适配和裁切，不将透明像素边缘当作者子槽 |

List 的库存展示使用数据与内部运行时几何，不接受借此新增任意作者子行。Select、RadioGroup 等即使内部有多个显示对象，也不能套用作者内容槽规则来替代其专有文字和交互检查。

## 统一几何口径

- **设计尺寸**来自节点 `size`；**求解尺寸**来自共享 Yoga 布局。fill、content 等规则下，校验应使用实际求解结果，不能只比较原始设计宽高。
- 内容矩形的 x、y、width、height 属于内容所有者的逻辑坐标；表面边距、标题栏、页签栏、按钮栏与滚动条预留都可能产生偏移。画布相机坐标不参与作者尺寸校验。
- 普通容器与允许滚动的内容区分开检查。允许纵向溢出不能同时放开横向边界，也不代表忽略控件或皮肤自身的最小尺寸。
- 隐藏子项不应仅因没有占用可见内容区而触发槽位溢出；结构、属性和资源绑定仍需合法，重新显示时仍须满足几何约束。
- 叶子控件的文字、标记、纹理和命中区域有各自合同；内容槽安全不代替这些检查，九宫格合法也不等于文字必然可读。

修复目标是让确定性文档检查、编辑候选、编译后的实际矩形与 Studio 安全区覆盖层使用同一套内容矩形及溢出规则。覆盖层用于解释约束，不修改作者节点，不自动缩小字体或内容，不替换皮肤，也不把真实限制改成警告。

## 本轮修复

以下问题已落到共享几何、运行时或编辑校验，保留真实安全限制。

| 问题 | 已确认的责任偏差 | 修复应保留的边界 |
| --- | --- | --- |
| 隐藏槽子项误报 | 槽位几何检查仍计入隐藏子项，可能把未显示内容判为越界 | 几何检查按可见性处理，同时保留节点结构、属性、绑定和重新显示后的检查 |
| legacy Dialog 编译检查错误禁止纵滚 | 旧编译路径用父外框限制内容高度，与 Dialog 适配器允许纵向滚动的行为不一致 | 允许合同内的纵向内容滚动，仍校验横向尺寸、标题及操作区预留和皮肤最小尺寸 |
| List 显式内容层使用外宽代替行宽 | 显式行没有统一按内容层扣除边距后的可用宽度处理，可能侵入侧边安全区 | 显式行、数据行、遮罩及实际行宽保持一致；不把整个 List 外宽直接当作内部可用宽度 |
| 单选组初始化/校验未扣全间距 | 初次创建用外宽均分，resize 才扣 gap；文字预检也曾用外宽均分 | `option-geometry` 集中实际单项宽度，初始化、resize、离线和真实字体检查共用 |
| 下拉框文字与弹出层口径不同 | 文字预检少扣一侧箭头预留；大字号多行弹出内容可高于整个画布 | 关闭面统一宽度；限制滚动视口，保留全部选项、行高与字体，至少一整行也放不下时明确拒绝 |
| 勾选图案偏心时可见像素越界 | 标记按底图可见中心对齐，极偏心底图可能让勾选图案越过逻辑 body | 保留中心与原像素；只对可见范围确实越界的图案等比限制，普通皮肤大小不变 |
| 文字状态与内容层遗漏 | 按每个状态分别扣边距低估共享标签的最大四边留白；List 标签漏扣表面边距，Dialog 动作漏扣实际放大边距 | 校验同一固定标签的最大四边 inset；使用真实行宽和 Dialog 内容宽度 |
| 装饰文字/标题核验对象不准确 | Text 按外框测量；带材质 Panel 按子对象序号寻找标题 | 使用 Text 适配器 textBox 与 Panel 显式 title 引用，安全区不由数组顺序推测 |

现场 `group-0` 高 255 缩为 254 的失败属于真实内容容量限制，不是上述误报。正确反馈应给出父安全槽、子内容求解尺寸、超出轴与差值，并提供定位；不能通过跳过安全检查、吞掉错误或提交更早的有效预览来修复。

## 验证状态

本轮 221 项定向 Node / DOM 与显示对象替身回归通过，覆盖 16 类型分类、表面层与放大边框、隐藏内容、共享 Yoga、编译边界、文字/标记/选项几何、实际 Select 方法、库存、编辑会话、保存来源与便携 JSON。只读冻结现场复现仍确认初始合法、分组减高 1 像素确实超出；未改原文档或产物。

编辑器默认提供**内容边界**开关：蓝色虚线为自身内容区，橙色虚线为父级可用区。这里的矩形来自同源几何并按实际渲染节点映射；滚动区标记允许纵向延伸，普通 List 的延伸仍是裁切合同，不代表新增滚动。槽位错误给出失败候选的可用尺寸、内容尺寸、超出轴与差值、当前内容要求的父容器下限，并可定位子项或父容器。这些反馈不修改布局、不自动缩小字体。

后续补齐普通 Container 的诊断缺口：固定行列累计、自由子项和共享 Yoga 的越界出口均附加失败候选 `layoutBounds`，包含所属容器、可用矩形、当前检查包络及超出量。自由子项和 Yoga 使用真实位置并显示四边差值；旧固定子项只报告宽高不足，不冒称 padding 锚定的尺寸包络是实际排版位置。界面不从上次有效文档推测数值，也不把当前累计占用宣称为完整最小尺寸；Yoga 的居中负起点和网格行偏移保持真实。固定布局隐藏子项不再仅因不可见的外框超出而失败，结构仍检查，重新显示仍须通过边界。新增 8 项回归覆盖行列一像素临界、负起点、网格、隐藏恢复、无效证据和会话回滚；扩展 227 项 Node / DOM 与几何回归全部通过，另完成浏览器模块静态构建检查。这轮没有操作浏览器或真实项目。
