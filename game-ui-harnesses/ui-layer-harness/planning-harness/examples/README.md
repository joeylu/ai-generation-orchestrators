# 合成示例：同一视觉计划贯穿规划与复核

visual-plan.json 不是实际图片识别结果，不含生成、审核或冻结回执。
示例假定 1000×1000 的原图，目的是展示输入输出关系。

本例采用 `editability:static-composite`。假定用户明确要求购买按钮及两枚金币
各自独立编辑，宿主才将这些对象列入 independentTargets。没有这项明确要求时，
默认列表为 []，仍须按重要视觉单元判断素材归属；空列表不要求把按钮和金币合入面板。
不得将本例的具体分组机械套用到所有参考图。

| 对象 | 区域示意 | 素材归属 |
|---|---|---|
| 场景 | 全画布 | asset-scene |
| 面板 | [100,100,900,900] | asset-panel |
| 顶部固定徽饰 | [400,50,600,160] | asset-panel |
| 购买按钮 | [500,750,800,850] | asset-buy-button |
| 第一枚金币 | [700,250,750,300] | asset-coin-a |
| 第二枚金币 | [700,400,750,450] | asset-coin-b |

按钮文案由宿主统一文字排除策略处理，不逐条输出文字框，也不生成文字素材。
示例对象分别使用 background、panel、decoration、button、icon 分类；
面板与徽饰虽 kind 不同，仍共享 asset-panel。分类没有改变素材数量或静态组合目标。
两枚金币的素材都使用 zOrder=3，素材框不相交；程序按素材 ID 排序派生不同 drawIndex。

- M1 产生 v5 示例形状的 JSON：6 个对象、5 份素材，不含 textRegions。
- M2 看原图/标框确认徽饰与面板一起保留，或直接修改 materialId 来拆开。
  若修改业务决定，只保存这份 JSON 的新版本，不另写素材决策合同。
- M1 直接声明 asset-panel 的框为 [0.1,0.05,0.9,0.9]，覆盖突出徽饰；
  M3 使用此框，得到像素区域 [100,50,900,900] 和中心 [500,475]，不求对象包络。
  示例仅徽饰保留辅助框，其余对象为 null；上表其他区域只是场景示意。
  这仍不是 Alpha 测量；缺少旧合同要求的证据时停止并报告。
- 复核证据与现有检查均满足后，首版对应 5 个图层、5 个待生成请求。
  这是条件推演，不是已经冻结或已经调用。两枚金币没有自动复用。

具体的尺寸/裁片、提示词和 request/batch 由程序产生，不出现在模型答案里。
