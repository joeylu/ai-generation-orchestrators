# 用玩家任务描述需求

Studio 首页仍以需求描述、生成按钮、修改要求、修改按钮为主。
输入框提示「说说玩家要做什么」，不要求用户先知道滑条、状态绑定或控件名称。
「不知道怎么说？看几个例子」默认折叠。声音设置、角色命名、加载界面的例子只描述玩家任务，
不夹带未展示的业务初值。选用会明确替换输入，可继续修改，不自动生成；选用后例子区收起。

例如可以先写：

> 做一个声音设置，让玩家调节音量、打开或关闭静音，还能恢复默认。

业务范围、初值和按钮作用缺失时，Agent 应提出具体问题。
推荐回答只是建议；用户可点选、改写或完全自己填写。回答不预选，
点选和「采用回答」均不调用模型。采用后再点击「生成面板」；修改流程同样处理。
原需求中已明确的事实应复用，不应再询问，外观继续使用所选目录的默认主题。

采用后的输入框显示问题和已选回答，省略未选建议。
完整问题保留在摘要绑定的规划上下文中；显示文本与该上下文须精确对应才能复用。
用户改写需求、标识或资源风格后，以新的可见内容重新准备，旧问题和选择失效。
多轮补充保留之前已采用的事实。完整问题不是授权，也不把未选建议当成业务依据。

生成后的「当前面板」摘要从已校验、编译的 PanelSpec 读取，而非模型自由撰写。
它概括控件，并在折叠详情里说明默认值、页签初始页、输入约束、进度和按钮的准确作用范围。
默认值与当前试玩值分开；修改默认值会保留试玩值，撤销会同步恢复摘要。
新方案未通过时，摘要仍属于正在显示的旧面板。密码默认值不以明文展示。

## 兼容的可选回答约定

公开方案的 `unresolved` 仍只含 `{id, question}`，版本和严格校验不变。
Agent 可在单行问题末尾附明确标记，例如：

```text
音量默认多少？【推荐回答：默认音量70。】【备选回答：默认音量50。】
```

至多三个回答、一个推荐，每个回答至多160个Unicode字符，总问题仍至多500字符。
不允许换行、嵌套标记、重复回答或标记后附文字。格式不符时完整问题按普通问句显示，仍可自由填写。
UI 只识别明确的标记，不从「音量」「默认」等关键词推断回答。
所有文本以文字节点显示。建议值仅在用户实际采用后才成为回答。
本地 Codex 的生成和修改提示共享此约定；外部 Agent 也可使用，旧问句继续兼容。

## 验证

```sh
node --test tests/*.test.mjs
node scripts/check-guidance-workbench-browser.mjs --workbench output/my-studio --output output/my-guidance-check
```

浏览器检查通过注入测试替身走真实的按钮、输入框、键盘、Pixi交互与撤销流程，
覆盖未填写回答、任意文本、格式回退、旧问题失效、连续澄清、摘要同步和390/768/1440像素布局。
测试不会调用真实模型；通过不代表真实模型每次都会提供推荐选项，未提供时仍可填写回答。
