## 生成与修改输出约束

PanelIntent 原生 schema 原先未限制数组数量，程序则严格拒绝空 children 或超过 96 项的容器。
现在 schema 同步限制 children 1–96、分组 rows 1–128、选项 1–8、Tabs 页面 2–8，
resetRows/submitRows 0–128；提示词明确禁止空分组和空占位节点。
全局 96 个布局节点、32 个分组、128 行和八层深度继续由程序校验，未放宽校验或自动补造控件。
上一轮只保存了 INTENT_COUNT 诊断和输出摘要，无法确认原输出是空数组还是过大数组。
新增 fixture 覆盖这两个违反边界的形状，均一次失败、零重试。

修改 schema 原先未将摘要限制为本次请求值。现在 root contextSha256 和非空 patch.baseSpecSha256
分别用本次经过验证的两个摘要作为唯一 enum。编辑提示词在首尾提供本次绑定，区分上下文摘要、
面板摘要和历史摘要。连续修改回归检查两次 schema 随当前面板更新；旧摘要仍会被公开验证器拒绝。
不覆盖模型返回的错误摘要，不替模型修复方案，不增加隐藏调用。
修改操作数组还保留公开 schema 的 1–32 边界。

## 口语检索与兼容

增加 slider-row 的“能拖的条、可以拖动的条、滑块、滑动条、拖动条”等词法提示。
16 条已保存口语需求现在全部能检索到所需的行配方；不将加载/进度展示视为可拖动滑条，
新别名也不对明确删除或否定该控件的短句加分。检索仍只是候选排序，不代替模型解释业务。

资产目录、请求原文和证据引用不变。别名确实改变候选排序时，新上下文包含
recipeRetrievalVersion:"0.2" 并将该版本纳入摘要；未受影响的请求保留原来的完整字节和摘要。
没有该字段的历史上下文继续按旧 0.1 检索规则复验，不以新规则重写旧计划。
实际生成评估计划也增加检索实现及编辑 schema 的源码指纹，改动后必须准备新计划。

## 连接与本地服务

模型服务连接失败仍为终止状态，保留原面板、试玩值、事件和撤销历史，未自动重试。
浏览器回归增加修改连接失败的保留检查。外部网络失败没有被声明为已彻底解决。
本地服务的 port:0 原先偶尔得到 Fetch 禁止访问的端口，导致测试报 bad port。
现在启动时只重新分配本地监听端口，最多八次；明确指定禁止端口会报 PORT_BLOCKED，
明确指定端口被占用也不会静默换端口。此过程不执行模型调用。
