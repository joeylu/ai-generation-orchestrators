# Decomposition / appearance handoff evidence

Scope: offline PNG ZIP import, original composite preview, captured semantic
document target, appearance contract validation and standalone JSON export.
No provider jobs, no changes to the upstream decomposition runtime, no artwork
reconstruction and no textured-control runtime integration.

The full automated run and implementation fingerprints are recorded in
[decomposition-appearance-verification.json](decomposition-appearance-verification.json).
Read that machine-produced status for the final regression outcome.

Focused browser checks exercise a genuine decodable procedural RGBA PNG inside
an upstream-shaped stored ZIP. They verify draft and automatic-QA disclosures,
original resource byte equality, explicit target capture, binding export and
restoration after reload. Negative checks verify invalid binding export is
disabled and a damaged replacement ZIP clears the previous material canvas.
The tests intercept the vision endpoint and assert zero requests.

An additional independent Python `zipfile.ZipFile` writer used `ZIP_STORED`,
sorted members and `archive.open(..., force_zip64=True)`, matching the upstream
writer's format choices. Pillow decoded the fixture successfully, and the
TypeScript importer accepted the Python-produced archive, retaining its draft
status and optional QA. Its SHA-256 was
`1f8b2ae4b52d8356bb442804b9d7d0ff1ab241b378d0083b20655604929ec5ae`.
This was file-format interoperability validation; a full upstream runtime run
was not performed. Importing the full upstream Python package in the bundled
environment required SciPy, which was unavailable.

The role vocabulary covers 16 component types. Runtime support, dynamic state
skins, repeated item mapping, nine-slice resizing, and visual fidelity are
separate acceptance requirements. No actual user decomposition ZIP has been
supplied for this milestone; the green Switch end-to-end artwork case and human
visual acceptance remain NOT_RUN.
