# 参考图工作台 · 本地网站 0.1.0

本地 React/Vite 工作台直接调用上层 UI Reference Harness 核心，不另写状态机。
支持项目创建与持久化、六种默认风格及本地样本、自定义规则包与 PNG、风格草案与激活、
ui-panel 原型导入、自然语言补充、首图锚点、其余面板计划、单次生成交换／可选适配器、
人工验收及完整 ZIP 导出。数据保存在本机文件工作区，默认仅监听 127.0.0.1:4186。

## 启动

从仓库根目录：

```powershell
npm --prefix game-ui-harnesses/ui-reference-harness/web ci --no-audit --no-fund
npm --prefix game-ui-harnesses/ui-reference-harness/web run build
node game-ui-harnesses/ui-reference-harness/web/server.mjs
```

打开 http://127.0.0.1:4186 。默认工作区为仓库忽略的 work/ui-reference-studio/data。
也可用 --workspace 指定私有目录，--port 指定本地端口。开发时 npm run dev 提供 Vite 中间件，
仍在同一端口、同一来源调用核心接口。修改后刷新页面。

可显式选择已经校验的外部默认样本包与只读示例项目：

```powershell
node game-ui-harnesses/ui-reference-harness/web/server.mjs --sample-catalog work/my-default-samples/catalog.json --showcase-project work/my-accepted-project
```

启动时校验目录交付与示例链，可能需要等待。参数路径不会通过页面配置或公共日志泄露。
不配置样本目录时，六种预设诚实显示为规则风格；不自动搜索宿主私有图片。
示例可查看和导出，不能激活风格、导入面板、授权、生成或写审查记录。

## 制作流程

「导入面板原型 → 示例原型」提供按游戏 SDK 合同整理的五类结构样本，共八份状态：开始页、设置（多语言）、暂停（在线／本地离线）、结算（完成／失败）、场景加载（加载中／失败）。先选类型，再选状态；缩略图和大图来自同一份原型，经公共 `ui-panel-harness` 编译后的可见节点绘制。示例导入不生成图片、不提交模型请求。

多状态 SDK 面板在项目列表、详情、锚点和图片导出中统一使用「面板类型 · 状态」，例如「场景加载 · 加载中」和「场景加载 · 加载失败」。已有项目同样适用此显示规则；不修改冻结原型、图内文案或生成记录，用户自行命名的标题保留。

默认样本按用户选定的组合提供：设置保留旧版600宽布局，通过独立的 `ui-reference-settings` 表现主题仅保留面板标题，采用三个开关、语言下拉和底部居中关闭按钮，去掉关闭分组标题与对应空位；开始页使用居中底板，标题和开始按钮居中排列；加载页以进度条居中为准，加载中使用紧凑底板、失败状态为恢复按钮保留高度，保留进度条上方的圆形加载占位，失败时在同一文案位置替换加载阶段，进度位置不变。暂停和结算保留 SDK 默认 skin 的显式几何，经公共生产器的 `fixed-reference-1` 只读模式完整校验和重放。960×800 视口下，设置底板为600×472，开始底板为520×300，加载中底板为600×208、失败为600×300，暂停在线为520×228，本地为520×308；三指标结算为560×448。成绩、语言和设置状态是明确示例值，实际项目按 SDK 配置；本套原型不执行 SDK 业务。字体字形与 DOM 行高仍取决于实际环境，不宣称运行时像素截图一致。

Boot Loader、运行错误面板和初始化失败提示保持系统界面边界，不列入普通样本。旧的三份示例文件、此前600宽通用排版、已有导入、风格样本及统一风格对照原型保留。通用排版与完整 SDK 布局分别可通过 `flow-sdk-*` / `fixed-sdk-*` 只读预览作对照，用户入口只展示选定组合；已有项目不自动替换原型。完整说明见 [SDK 示例原型](docs/sdk-panel-examples.md)。

1. 填写项目名称，选择默认风格，或选择自定义风格并上传参考 PNG、填写可选描述，核对草案后点击「确认风格并创建项目」。
   最终确认前仅有未发布的风格草案；任一步取消、关闭或 Esc 都不会新增项目。
   六种默认风格和「自定义风格」放在同一组选项中；选中自定义后显示参考图和风格描述。
   自定义风格只提供参考 PNG 与风格描述，至少填写一项；不提供高级设置、基础风格或 JSON 上传，也不继承此前选中的默认风格。程序以遵循用户参考图与描述的独立规则冻结自定义输入，不预设流派或配色。
   直接选择默认风格且没有补充时，「确认」沿用默认样本并进入风格核对页；最终确认后才创建项目或更新项目风格。
   填写「项目风格补充／风格描述」或选择自定义风格后，选择页显示「确认并生成预览」。一次点击完成整理与生图：有补充时先调用一次文本解析，覆盖基础风格中对应的项，并协调配色、色彩语言、材质、光影和限制规则；随后用完整规则、原始样本和统一设置原型生成 1 张新图。没有补充时不调用文本解析。
   等待时留在选择页，分别显示整理与生图进度；完成后直接展示新图、最终配色、完整规则和补充摘要供核对，不再要求到第二页点击生成。解析失败不开始生图；生成失败进入核对页保留记录，须主动点击「重试生成预览」才能新建尝试，没有新图时不能确认采用。
   每次生成点击冻结独立计划并单次提交，读取结果、刷新和重复请求均不重新生成。成功出图后不显示重新生成按钮；需要修改效果时点「返回调整」，修改补充要求后重新确认生成。仅预览未完成时保留重试入口，不自动重试；直接使用默认样本时不显示额外生成按钮。
   新图完成后仍待人工确认；检查布局、风格与文案，再点击「确认新图并创建项目／使用此风格」。程序将新图设为新风格修订的主参考，后续面板继承它；原始样本与规则保留。预览使用隔离项目，不添加用户面板、不建立面板锚点。预览记录保存在私有 `style-previews/` 中。取消不会发布新项目或改变已有项目风格。
2. 点击项目标题区的主按钮「导入面板原型」，默认打开上传入口。选择 ui-panel 导出的 JSON，自动识别 PanelBundle 或 PanelSpec；识别为规格文件时可补充配套控件目录，省略则用内置目录。原型截图仍可选。
   「示例原型」提供五类、八种 SDK 状态，显示缩略图及所选状态的大图。预览由上游编译的实际布局和初始可见文案绘制，为布局示意，不是生成的风格成图。
3. 导入后直接打开面板，填写可选「面板补充」，点击一次「生成参考图」。已配置适配器时，程序自动冻结输入、将这次点击绑定到计划摘要、单次提交并完成技术检查，不再经过准备／授权／提交多个页面。
4. 查看结果，点击「接受这张图」明确确认布局、风格与文案；或填写「修改意见」后点击「修改并生成」。首图之后最多三轮修改，每次只生成一张图片。已提交但失败或结果未知的修改仍占一轮；适配器预检失败不占轮次。不自动重试。
   验收须等待当前大图加载成功；切到原型或图片加载失败时不能提交验收。加载失败会提示关闭后重新打开面板，保留图片与生成记录。
5. 每个面板按项目风格和原型摘要保存会话、草稿、意见及图片版本。刷新、关闭窗口或重启后可继续；生成中保留上一张图。旧的技术合格图片可直接接入会话，不必重生成。多个窗口的过期操作会被拒绝，重复请求不会重新提交。
6. 首图接受时可明确设为项目锚点，后续面板共同继承同一风格与固定锚点。未配置适配器时保留手动输入 ZIP／PNG 交换流程。
7. 所有未删除面板接受后点击「导出项目」，下载仅含 PNG 的图片 ZIP，按面板名称命名，同名自动编号。旁边的「更多导出选项」可下载带风格、原型、来源及校验记录的完整交付包。下载文件名分别为「项目名称-reference-images.zip」和「项目名称-references.zip」，保留中文，替换文件名中的非法字符。两种下载均先通过核心完整交付校验；历史完整包下载链接保留原格式。

面板列表与详情预览展示最近一次有图片的结果；有未接受的优化结果时，整套导出仍使用最近接受的版本。
卡片根据当前状态显示「生成参考图」「验收图片」「查看与修改」等操作；点击只打开面板窗口，实际生成仍由窗口内明确点击触发。只读示例显示「查看图片」或「查看原型」。
「查看锚点」始终打开最初固定的锚点图片，优化同一面板不会替换它。
生成发生错误时会重新读取已保存状态，不自动重试；结果未知的尝试不能再次提交。
会话文件保存在私有工作区 `panel-sessions/`，不进入公开交付。Codex CLI 适配器另外保存实际 thread ID，已完成的会话通过 `thread/resume` 继续，每轮仍使用新的冻结输入和单次调用限制；未知状态保留原线程，不恢复提交。
单个项目文件损坏会单独标记读取失败，其他项目仍可使用。
已支持的历史版本中，完成技术检查的参考图及风格预览可继续读取和人工验收；未完成的旧版任务仅可查看记录，不提供当前版本无法执行的生成、导入结果或处理按钮。完成原任务须使用生成时的兼容版本；新生成使用新计划和新的明确决定。

## 删除与恢复

### 删除与恢复面板

每张面板卡片都有删除按钮，确认后从当前列表和后续导出中移除，可在当前项目的「已删除」筛选中恢复。
待生成、生成中、失败、待验收、已接受等状态均可删除；取消不会改变面板。只读示例不能删除。
删除仅更新工作台可恢复的可见性元数据，核心注册原型、会话、冻结计划、原始输出、验收与已有交付包均保留。
已经提交的任务继续收尾，不取消提供商请求、不重复提交，结果不会使面板自动恢复；删除后不能新建计划、生成、修改或验收，恢复后沿用原会话和剩余修改轮数。
固定项目锚点独立保留，即使删除其来源面板，后续面板仍沿用该锚点。新导出仅选择未删除面板，响应中列出 `excludedPanelIds`；已有交付包保持原样。
该可见性设置属于本地工作台，不修改 CLI 项目注册表；直接使用核心 CLI 时仍能访问原有面板记录。

### 删除与恢复项目

打开自己的项目，在标题区的「项目更多操作」（···）中点击「删除项目」，确认后移入左侧「回收站」。
取消、关闭或 Esc 不会删除。回收站中点击「恢复项目」即可回到原项目继续制作。
删除仅原子更新工作台元数据，原型、风格、锚点、生成记录、图片和已有导出文件全部保留；
恢复沿用原项目 ID 和原记录，不重建项目、不重新授权或生图。当前不提供永久清空。
项目在回收站中时，普通查看、写入及原下载链接均不可使用；恢复后重新可用。
正在通过工作台生成时不能删除，只读示例项目也不能删除。

界面支持 PNG 最大 20 MiB。JSON 风格包仅保留在核心／API 接口中，通过原始字节冻结；含 references.primary 的包可配套提供主 PNG。
JSON 包仅为数据，不执行脚本，不接受角色专用包或提供商配置。项目风格修改产生新修订，
旧图保留并标记待更新；新修订须建立自己的锚点。布局改变应重新导入上游原型。

可选 --adapter 指向显式配置的本地 ESM 适配器，接口沿用 [核心合同](../docs/contracts.md)。
适配器由本机拥有者配置，网页不能上传模块或输入凭证。未配置适配器时不伪造生成结果。
请求保留之后禁止再提交；未知结果需要明确终止，不能自动重试。已保存 raw 可在原摘要下完成本地处理。

## Codex CLI 适配器

图片 Hook 仅传冻结提示词和有序本地参考图，不注入 `transparent_background`，以兼容严格原生工具。
不透明要求仍由提示词和核心逐像素 PNG 检查保证；Hook 改版后须重新核对可信摘要，旧失败任务不自动重试。

`adapters/codex-cli.mjs` 是可选的本机适配器，默认使用 `gpt-6-luna`、`xhigh`。
通过安装好的 Codex CLI 的 stdio app-server 协议调用内置生图工具，无额外网络监听、API 密钥或网页凭证输入。
CLI 需要已通过 ChatGPT 登录，并支持内置生图与 hooks。

```powershell
$env:UI_REFERENCE_CODEX_BIN = (Get-Command codex).Source
$env:UI_REFERENCE_CODEX_WORKSPACE = Join-Path (Get-Location) 'work/ui-reference-studio/codex-cli/jobs'
node game-ui-harnesses/ui-reference-harness/web/server.mjs --adapter game-ui-harnesses/ui-reference-harness/web/adapters/codex-cli.mjs
```

适配器使用两条专属的 PreToolUse/PostToolUse 脚本限制调用。先在 CLI 中检查并信任其确切定义；
脚本路径或内容改变后需要重新核对。未完成时网页显示配置提示，禁止开始计算，不消耗尚未提交计划的授权。
适配器不自动修改全局信任配置，也不使用信任／沙箱绕过开关。
本机拥有者可以通过 Codex 正式配置接口登记这两条已审查定义的 `trusted_hash`，不能信任无关脚本。

预检仅运行登录状态、功能、离线模型目录和 hooks/list；不会启动模型回合或生成图片。
实际生成使用临时 CLI 会话和只读沙箱，冻结提示词及有序原图，关闭无关工具和传输重试。
图片调用前以独占文件保留请求，脚本强制同一提示词、同一有序参考图及不透明输出；
收到首张 PNG 后结束 CLI 会话，由原核心保存原始字节、检查并完成后处理。
工作台以冻结计划摘要隔离私有执行目录，同一计划跨进程／重启仍不能重新提交。
另行明确授权的新计划可使用相同输入，旧尝试和文件完整保留；直接使用适配器而未提供计划摘要时仍按请求摘要隔离。
私有目录保留有上限的执行阶段和结构化错误类型，不记录提示词、图片、凭证、原始错误消息或 stderr。
页面展示模型及实际准备状态，失败不重试。

可选适配器可以提供 `resolveStyle({ base, notes })`，返回完整 `render_style`、`ui_rules`、五色 `palette`、`negative_rules` 和中文 `summary`。它只供显式带 `resolveNotes: true` 的风格草案请求使用，旧 API 的 notes 仍保留原先的补充语义。
Codex 适配器使用同一 Luna/xhigh 配置启动一次独立、临时的文本回合；禁用生图、shell、外部插件与传输重试，使用 JSON Schema 约束结果。它不恢复或占用面板的图片 session，不生成媒体。
完整合并结果通过现有核心冻结为新的自定义风格包，替换发生冲突的规则（包含限制规则）；原始包、参考图和基础风格修订保留。只有用户核对并最终确认才激活。文本解析的输入／输出记录放在私有 CLI 工作目录的 `style-drafts/` 下，不进入公共交付或日志。

旧的输入包交换任务可以继续一次：必须确认未向其他图片工具提交，并绑定原请求摘要；
工作台已有提交记录、请求摘要不符或尝试已终止时拒绝。程序沿用原核心保留记录，不重新授权、保留或改写它。
结果仍须用户检查布局、风格和文案后接受；不会自动设为锚点。

## 验证

```powershell
npm --prefix game-ui-harnesses/ui-reference-harness/web test
node --test game-ui-harnesses/ui-reference-harness/tests/*.test.mjs
```

接口测试使用临时项目、程序绘制 PNG 和模型替身，不调用真实图片服务。
tests/browser-fixture-host.mjs 是显式隔离的浏览器测试服务器（4187），只返回合成图片；
不进入 npm start，不作为在线提供商或真实视觉证据。
测试工作区／截图保持在忽略的 work/，不将真实默认样本或用户项目捆绑进前端构建。

本网站是当前用户授权的本地工作台例外，不是部署、认证、数据库或生产发布入口。
