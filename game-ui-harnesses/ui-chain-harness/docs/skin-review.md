# 两套皮肤统一验收

从 Harness 目录运行：

```powershell
npm run skins:review -- build
npm run skins:review -- serve
```

维护入口是 configs/skin-review.json：皮肤标识、显示名、assembly.json 路径及固定本地端口4194。添加皮肤时更新该列表；不编辑生成页面或复制组件代码。

build 逐套调用统一后处理，校验组包、独立加载、交互与组件状态，随后生成一个验收页面并运行浏览器切换检查。全部通过才发布 work/skin-review/current.json；失败不会替换上一入口。不调用模型。

页面可切换皮肤、16:9/9:16画布；全部组件模式用于总览，单组件模式提供180/276/420三档宽度和初始/更新值/禁用状态。状态只适用于有对应能力的组件。切换重置交互，不修改任何源JSON。画布保持设计尺寸，可在窗口内滚动查看。

已有后处理结果可通过 --runs work/.../runs.json 复用，该文件是皮肤id到后处理结果目录的映射。程序核对配置摘要、消费包摘要、当前运行时源文件、依赖锁及两套包的共享运行时/示例一致性，过期结果须重建；这是运行缓存，不新增维护源。

每个构建目录保留两套来源、包摘要、回归数量、页面文件清单、106组页面检查记录及横竖截图。验收页仅提供清单中已校验的文件，监听127.0.0.1。服务展示启动快照；构建新版本后需重启同一端口，不会改变已打开的旧端口。

工程检查通过不替代视觉接受或正式发布。本入口不包含布局规划器和画布编辑，也没有自动修切线或自动生图功能。
