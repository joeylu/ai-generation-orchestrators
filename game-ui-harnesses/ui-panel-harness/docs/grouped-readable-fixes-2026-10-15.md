# 十个面板的宽度与分组修复

本轮按已审阅的十份真实模型结果修复默认规则，并生成同源离线前后对照。新增真实模型调用 **0**；原始交付、ZIP、收据和既有问题报告保持原样。设置的音频／画面拆分采用明确的人工审阅映射，不是新模型回答，也不是运行时根据中文标签猜测分类。新提示词尚未进行真实模型复测。

## 默认行为

Studio 与 SDK 默认目录改为 `modern-readable-game-grouped-layout`，主题 `0.29.0`／`0.29.1`、`game-readable-v3`、Compiler `0.42.0`。正文与按钮仍为24、主标题32，默认普通单列420、暂停菜单360。原来的0.41及更早目录继续随包保留；十份0.41原始包的完整摘要逐一精确重放通过。

- 长 Select 标签放在控件上方，选项在紧凑控件内完整换行；List／RadioGroup 根据完整文字测量行高。选择ID、原始标签、状态、事件和重置范围保持不变。
- List 的 `itemHeight` 在新目录中作为最小行高，按文字增加到最多96逻辑像素；过长文本超出该公共契约时明确报 `CHOICE_WRAP_HEIGHT`，由调用方选择更宽的明确布局或调整文案。不会截断文字或缩小字体。旧目录的行高行为保持。
- `sectionSurface:panel-v2` 为含 `settings.text` 数据的内容组生成底板。`message.text` 确认问句与纯按钮操作组保持简洁。标题、控件标签和正文的含义不变。
- 实际短口令提示路径明确要求音频／画面等有意义类别各用一个组、同类控件共用底板、独立操作另放按钮组。运行时不读取外部skill。语义分类仍由模型决定；确定性程序只负责排版、校验与呈现。
- 明确给定的面板／画布尺寸、字号和滚动约束继续优先。新的换行高度、菜单预留空间和分组内边距一起参与测量，空间不足时拒绝交付。
- Unity 导入工具版本 `0.1.8` 允许选择标签中由编译器产生的显示换行；保留原始选项ID和源文案长度上限，其他控制字符仍拒绝。保存包的业务Spec保持原文；原生交付使用同一份完整显示标签。没有运行Unity原生编辑器验收。
