# 面板比例与固定尺寸

已生成的 modern-v3 面板支持精确比例与固定宽高编辑。例如：

- 把面板改成 16:9 横版，宽 640，保留文字字号和按钮行为。
- 改成 9:16 竖版，宽 480，内容重新排版，空间不足时滚动。
- 改成 600 × 600 的正方形，保留当前输入。
- 取消固定比例，恢复按内容自适应高度。

比例作用于实际面板底板。画布另行留出边距和下拉菜单空间，因此画布尺寸不等于面板尺寸。Studio 在预览下同时显示这两项；内容少时也保留固定高度。字号和控件尺寸不随比例整体拉伸，已经声明自动换行的正文重新测量高度，普通横向分组在窄版中换行，内容过高按现有 overflow 规则滚动。

## 结构化编辑

比例能力从 EditContext 0.9 提供，声明 `panelFramePolicy: fixed-panel-frame-v1`；Studio 当前新编辑为0.10，另外支持[同轮修改内容布局](panel-layout-details.md)。CodexEditDraft 仍为 0.3，两个尺寸操作为：

```json
{"op":"set-panel-ratio","ratio":{"width":16,"height":9},"width":640}
```

程序计算高度；`width: null` 保留当前面板宽度。比例两项均为 1–1000 的整数。

```json
{"op":"set-panel-frame","frame":{"width":600,"height":600}}
```

宽度为 1–4096 整数，高度为 1–4096 有限数。高度允许逻辑像素小数，例如宽 480 的 9:16 面板高度为 853.333…；预览标签显示两位小数，包内保留原数值。`frame: null` 清除固定高度约束，保留当前宽度、高度上限和画布，恢复按内容计算实际高度。

两个操作均生成 Spec/Bundle 0.14，编译器为 0.14.0，根字段 `frame` 必填且可为空。非空时 `layout.width` 必须等于 frame.width，`layout.maxHeight` 必须等于向上取整后的 frame.height。操作会同步计算画布；不能在同一补丁内与另一个 frame 操作或旧 set-layout 混写。EditContext 0.10可在同轮使用 set-layout-details 修改内边距、标题区域高度等独立内容属性。

公开 API `createPanelEditContext(spec, catalog, request, selection, {panelFrame:true})` 可显式启用新能力；0.14 规格自动使用新上下文。旧规格的 API 默认行为、已保存的 0.8 上下文和旧交付包保持原版本。生成协议仍为 PanelIntent 0.10 / PlanningContext 0.9，本次仅扩展现有面板编辑。

## 保留与边界

修改保留存活控件 ID、当前试玩值、绑定及动作；成功应用计入原有十轮上限，失败和无需修改不计数。选中了单个控件时不能调整整张面板，应先取消选择。

这不是任意尺寸都能通过：明确指定的子节点宽度、圆形按钮尺寸和不换行文字仍须放得下；宽高过小、滚动区容不下一行、画布 4096 上限或菜单空间不足会整批拒绝，原面板保留。正文换行和排列规则不会改写用户已有的显式控件尺寸。

Pixi 预览、离线交付和 Unity UGUI 导入文档共享同一编译结果。组合器接受 0.14 来源，但组合后的外层几何由组合请求决定，不继承来源面板的固定 frame。Unity Editor 原生导入应单独验收，程序导出通过不等于原生运行通过。

`examples/panel-frame-v1/fixture.mjs` 提供横版、竖版、取消固定高度的 authored 修改链；`tests/panel-frame.test.mjs` 覆盖比例、滚动、页签、状态、原子拒绝、十轮限制和零模型传输替身。这些夹具不代表真实模型的自然语言命中率。
