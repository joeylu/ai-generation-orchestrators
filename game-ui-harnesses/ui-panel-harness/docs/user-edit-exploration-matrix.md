# 用户需求探索清单：72个新增场景

这是测试设计和能力缺口审计，不是执行报告。按当前Spec 0.9、EditContext 0.3及Studio合同整理；本轮新增模型调用为0，下列场景均为NOT_RUN。之前40例的通过记录保持独立，不能替代本清单。

后续实现说明：Spec 0.10/EditContext 0.4和原生生成Intent 0.9已补入同组重排、单按钮样式、Text正文及初次按钮排列，见[新增合同](panel-control-editing.md)。下表保留审计时的缺口与NOT_RUN状态；新增确定性回归不能自动把72条自然语言用例改为已通过。

最新补充：Spec 0.12/EditContext 0.7增加按钮独立字号、面板标题对齐/字号/底板。[28条边界审计](edit-boundaries-audit.md)已执行20条作者方案程序用例，并单列8条剩余缺口；未实测模型自然语言解释，不改变本表历史NOT_RUN记录。

目标是让日常表达映射到明确、可校验的修改，不要求用户学习ID、控件名、颜色码和像素。纯视觉偏好可选合理默认值；业务含义不明、指代不唯一、要求互相冲突时才提具体问题。

## 基准与判定

- M：音乐播放器，一个纯按钮分组，依次为上一首、播放/暂停、下一首。按钮内为图标字符，行label为空，各自通知宿主。基准纵排；圆形版为横排56×56、间距16。
- F：角色表单，角色名单行输入初始空、必填、最少2最多12个UTF-16单元。确认提交角色名，取消只通知宿主。试玩名字“小蓝莓😀”。
- S：声音设置，主音量0..100、步长1、默认70；静音默认关，开表示静音；恢复默认只重置两项。试玩音量83、静音开。
- T：声音/显示两页签，各含滑条及只重置本页的按钮。主音量默认70、亮度默认60，各0..100、步长1。试玩在显示页、亮度81。

“其他不变”独立核对稳定ID、控件数量、绑定、事件、动作范围、未涉及的外观和当时试玩值，不只看协议是否通过。

| 预期类型 | 判断方式 |
| --- | --- |
| 应用 | 合同可表达，状态和几何门禁通过后应整批应用，不能虚报能力不足 |
| 澄清 | 缺失信息会产生不同业务或目标，只问阻塞问题 |
| 冲突 | 要求不能同时成立，指出具体矛盾，不偷偷选择一项 |
| 缺口 | 当前合同无法完整表达，说明未支持的部分，不能冒充成功 |
| 无变化 | 当前已满足或明确不改，不增加轮次 |
| 流程 | 验证实际操作、持久化与运行边界，不能只看模型方案 |

缺口解释正确与用户愿望得到满足分开统计，不能靠增加拒绝率做高成功率。“应用”只表示合同可表达，不代表已通过真实模型测试。

## 优先补哪些基础能力

1. 移动现有行及按钮子集排列：稳定ID不变，事件、状态和reset/submit依赖保留，处理显式布局的影响。覆盖B03/B05和“取消放左边”。
2. 单控件样式/尺寸：主题→面板覆盖→控件覆盖，只开放有限可校验字段。覆盖A05/B04/C02/F04，不用全局样式勉强完成。
3. Text正文编辑：区分标题、行label、按钮文字和正文，覆盖D01。
4. 状态范围/枚举选项编辑：先定义当前值不兼容时的迁移政策，再开放操作。覆盖D02/D03；不自动钳制、清空或替用户选值。
5. 可见性、条件启用及按钮状态：独立声明式规则，覆盖E03/E04/E06；复杂动画、任意脚本和联网业务保持边界。
6. 生成/编辑共享呈现能力：覆盖I01；需要新增生成合同及独立验收，不能只改提示词。

建议首批12例：A01、A03、A05、B03、B04、B05、C04、D01、D02、E03、F05、I01。兼顾新能力验证和合理需求缺口。这是待测选择，不是模型调用授权计划。

## 怎样继续扩展

沿六个维度变形：目标（全局/单控件/子集/跨页）、属性（颜色/尺寸/位置/文字/状态/行为）、表达（明确/口语/错字/中英混写/指代）、状态（空/已试玩/已有覆盖/第9轮/第10轮）、组合（单改/多改/支持与不支持混合）、过程（连续改/撤销/刷新/导出/并发）。

先跑高频单项，再做两维组合覆盖；状态迁移、依赖删除、轮次和存档补专项序列，不需穷举笛卡尔积。保留失败原文，拆出最小复现，再加同义表达和反例，避免只修固定句子。

分别记录需求覆盖率、已支持需求模型命中率、误拒绝率、多余澄清、漏改、非请求属性变化、试玩值保留、渲染/交互、导出一致性。每份结果绑定源码、协议、基准和原文；夹具通过、真实模型通过、已知缺口分开。
