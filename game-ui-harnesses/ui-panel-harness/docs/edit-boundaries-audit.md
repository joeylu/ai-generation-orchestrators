# 用户修改边界审计

本轮把28条用户表达落到可复核清单：[输入和作者方案](../examples/edit-boundaries-v1/fixture.mjs)。这是现有面板的修改审计，初次生成能力另行验收。没有调用模型；不能把作者方案通过解释为模型能稳定理解这些话。

运行：

```powershell
node scripts/check-edit-boundaries.mjs --output output/edit-boundaries-audit
```

输出目录必须全新，限定在本Harness内。命令只用程序夹具，绝不启动真实模型。它保存当前源码/协议/提示/Unity适配器摘要、上下文、作者Draft、结果、修改前后包、UGUI文档及交付ZIP。产物不覆盖历史运行。

## 这次实际检查了什么

- A01–A14：标题字号/对齐、单按钮字号/字色/尺寸、不同尺寸横排居中、控件换序、替换内联符号、正文文本、组合修改、清除局部样式、行标签、只读输入、默认值与试玩值分离、删除字段并更新重置范围。逐项检查具体效果、非请求属性、稳定ID、事件、状态、整批撤销和轮次。
- A15–A16：无变化与澄清的作者返回，确认原面板和轮次不变。这验证程序处理，不验证模型是否会提出正确问题。
- R01–R04：超大按钮字号、放不下的标题字号、不存在的控件、所选控件作用域冲突。前半句有效也不能部分提交。
- 每份成功修改生成实际交付ZIP，独立校验CRC、文件字节数、SHA-256与Pixi/Unity Bundle重新编译。本命令不验证浏览器像素和Unity编辑器原生导入。

20条程序用例结果：14条作者修改方案通过、4条非法批次完整拒绝、1条无变化、1条澄清，失败0。8条缺口单独记录，不能算作已满足的需求。

## 当前缺口

| 场景 | 当前边界 |
| --- | --- |
| 正文自动换行，后续控件自动让位 | Text编译为单行，缺少换行与测量高度合同 |
| 普通行标签和分组标题独立字号/对齐 | 已有标题样式仅作用于面板标题；按钮字号仅作用于按钮 |
| 按钮内位图替换与独立缩放 | 内联字符可替换和调字号，图片不是同一能力 |
| 静音后禁用音量 | 只能静态设置启用，缺少状态驱动条件 |
| 播放后变暂停符号 | 按钮文字是静态的，缺少显示状态绑定 |
| 给控件子集加共同底板并重组层级 | 没有任意子容器或重分组操作 |
| 手机/电脑不同排列 | 固定逻辑画布，缺少断点规则 |
| 只恢复历史颜色 | 修改上下文没有可选历史属性快照 |

## 本轮提示修复

移除“其他文本都不能单独调字号”的笼统限制，明确面板标题、按钮、普通行标签和正文各自的能力。补充多要求完整性规则及静态字符/图片/动态状态的区别。同组横排不同高度按钮实际自动上下居中，不应因没有单独对齐操作而误拒绝。

## 已观察到的语义限制

程序构造一个故意漏项的方案：原文要求“标题改名，并在静音时禁用滑条；两项全部完成”，方案只改标题，却引用完整原文。它能通过结构校验。该探针没有应用，也没有调用模型；报告标记 `SEMANTIC_LIMIT_OBSERVED`。

这说明合法结构与原文引句不能证明全部需求已满足。提示要求完整覆盖能减少漏项，不能替代真实模型验收。后续真实测试应独立比较每项需求与最终行为，记录误拒绝、多余澄清、漏改及非请求修改；不能只统计协议通过率。

后续实现：已补[正文换行与内容高度](panel-text-wrap.md)，面向已有 modern-v3 面板的静态正文编辑。上表及原报告仍保留审计时的缺口结果；本轮程序验证不回填为历史模型成功。条件联动仍需要单独的声明式规则合同，不通过自由脚本实现。
