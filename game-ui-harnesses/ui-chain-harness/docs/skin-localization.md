# 模板约束定位：候选与边界

当前实现的是保守定位诊断，不是可直接替代人工配置的自动拆分。入口一次处理全部四板，不调用模型、不改图片、不覆盖已验收的 assembly.json。

```powershell
npm run skins:locate -- --input work/skins/orbital-hangar/localization-input.json
```

输入为 `kind: ui_skin_localization_input`、`version: 1.0`、`templateSha256` 和 `sheets` 数组。每板包含 `sheetId`、相对输入文件目录的 `file`、原字节 `sha256`，必须完整覆盖模板四板。文件限制在安全相对路径；模板和原图摘要不匹配则停止。日常只维护模板槽位，定位输入仅绑定本次四张原图，不增加手工裁切坐标。

## 方法

从模板 slotRect 等比例换算原图坐标，不重采样图片。对所有alpha非零像素做8邻接连通分析，记录各连通块的矩形、像素数、最大alpha及alpha总量。完全不透明的图不支持，非等比尺寸拒绝；最多分析10000个连通块，超过则明确不支持。

只有槽内单一连通块且边界完整留在槽内时才返回候选裁切。缺件、多连通块、触边或跨槽均返回歧义，裁切为null；槽外连通块阻止整板成为无歧义候选。不静默忽略单像素、阴影、半透明装饰，也不把最大的块自动认定为主体。

候选的身份仅来自槽位约定：模型把错误部件画进正确槽位时，本方法不能识别。报告一直标记 `semanticIdentity: not-verified`、`assemblyReady: false`，不会自动生成可执行assembly或接入后处理。分离装饰和多块结构也可能合理，目前保守地要求复核。

## 主体与碎片关联提案（0.68）

严格定位结果保持原样，新增独立 `association` 报告，不把提案冒充严格无歧义候选。规则维护源为 `configs/skin-localization-policy.json`，只是内部试验策略，不是用户日常调参入口；每次运行记录策略快照及算法摘要。

- 默认将整个连通块最大alpha不超过2/255的块视为极淡候选，其余视为较明显的块。该阈值只决定关联提案，不改变任何像素，不证明淡块是噪声，也不是生产准入阈值。
- 较明显块只在与唯一槽位相交时归属；跨多个槽位的块保持冲突，不靠最大面积、最近中心或旧裁切坐标猜归属。唯一归属但超出本槽的块保留完整矩形，并标记跨槽。所有较明显的分离小装饰均纳入，不按面积删除；多个明显块同时标记待核对。
- 极淡块只有在距唯一一组明显块的矩形不超过4个逻辑像素时附加，距离按原图倍率换算。只比较原始锚点，不递归扩张，防止碎片链桥接相邻部件。邻近多个组或没有邻近组时记录为未关联。
- 输出联合外接矩形作为 `proposedCrop`。矩形内原像素全部保留，可能仍含未关联碎片；当前不生成修图或切除结果。报告精确逐像素统计全部提案覆盖范围的并集与框外像素/alpha总量，重叠区域不会重复计数；各槽内还分别统计本提案未覆盖内容。框外不等于可丢弃。
- 多槽冲突不返回裁切提案；无明显锚点的低透明度艺术内容也保持未解决，不当作空资产。提案之间重叠明确标记。所有提案都保持 `needs-review`、`assemblyReady: false`、身份未验证。

## 独立裁切对比（0.69）

新增 `skins:locate-compare --report <定位报告> --input <原定位输入> --assembly <已有assembly>`。三项路径均位于work下。程序检查输入/模板/原图/基线素材摘要，仅在原字节同源时比较，输出到 `work/skin-localization-comparison/<ID>`，保存比较报告与输入快照。基线不反馈给定位算法，也不是完整的部件语义真值。

逐像素分别统计共同区域、基线独有及提案独有的非零像素数、alpha总量和最大alpha；另检查提案与同源其他基线裁切的可见像素交集。没有交集只表示未触及这些已知裁切区，不能证明区外不存在其他装饰。1项差分测试通过，覆盖低alpha、透明RGB、相同裁切和越界拒绝。

- 机库报告 `work/skin-localization-comparison/cf1b1a0c-b865-47a1-899d-0a8f5ef60d23`：30件同源比较，0件漏取基线可见像素，0件碰到其他基线可见区域；26件多取可见像素，新增最大alpha为7/255。矩形大小变化仍可能影响后续等比装框和素材密度，所以不能仅按透明度低就自动接受。

森林S03诊断：程序记录冲突矩形与槽位交集的像素统计（窗口内所有原图像素，不冒充连通块独立蒙版统计）。横轨矩形 `[151,92,949,117]` 延伸至第二槽，交集最大alpha为4；填充条矩形 `[148,269,953,119]` 下伸到从y=372开始的后续槽位，部分交集有alpha255像素。开发期查看原图可见两条横条独立存在；这里主要是原图排布偏移/尺寸偏离模板造成多槽相交，而非证明多个控件已粘连。此查看仅开发诊断，不写入程序接受状态。

下一步应评估按连通块在各槽位的实际像素分布区分“主要归属”与“越界影响”，同时保留溢出提示；不能仅把相交判定换成最近中心或最大面积就放行。原图、assembly、组件预览、全部历史报告保持不变。

## 实际像素主要归属（0.70）

定位遍历每个连通块时直接累计其在各槽内的非零像素数与alpha总量，排除外接矩形中属于其他块的像素。关联策略增加 `primaryOwnership`：一个槽须同时覆盖整块至少60%的非零像素和60%的alpha总量，且其他单槽各自的像素/alpha份额均不超过20%，才提出主要归属。分母包含槽外像素，不会把大量槽外内容排除后虚增比例。这是内部实验启发式，不是置信度或质量接受标准。

归属接近、像素数与alpha判断不一致、主要内容在槽外时仍未解决。缺少新像素分布的旧报告不能直接套用新策略，须重新定位；旧证据保留。无新策略字段的调用仍使用原矩形规则以便回归对比。

跨槽块归属后保留整个连通块，主体越界、提案越界、其他槽内出现外来连通块都单独提示；没有切掉跨槽部分。块的主要归属和其影响范围明确分离，仍不证明部件语义正确、不自动接受。
