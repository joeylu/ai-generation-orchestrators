# 用户输入覆盖补强 · v2

用户指出生成面板的输入形式尚未覆盖充分。本轮在原[40项真实验收清单](user-input-test-matrix.md)和[72项需求探索清单](user-edit-exploration-matrix.md)之外补充24个有明确预期的场景，不把它们计入既有真实通过数。

`src/input-interpretation.mjs` 将同一组阅读约束接入原生生成、旧生成运输和编辑提示：区分明确纠正与未解决的矛盾，区分示例/旧方案/问题与最终回答，保留否定词标签，检查排除条件、同名对象与点选范围，并逐项核对混合请求。不支持或仍有歧义的必要部分应整批澄清；不能把完成其中一部分说成完成整项请求。

生成提示原来要求使用请求中出现的默认值，容易混淆“原值70，更正为50”中的两个值。现在明确要求结合上下文采用最终回答，禁止把示例或被更正的旧值当作本次事实。`requestReading` 仍是无损字面阅读辅助，不解释语义、不选择默认值。程序没有新增任意自然语言分类器，也不会重写模型输出。

## 能证明什么

`tests/input-coverage-v2.test.mjs` 的26项检查通过：24个上述夹具，以及独立期望的反例校验和提示约束检查。成功编辑保留未涉及的绑定、动作、资源、试玩值；澄清与无需修改保留面板摘要，额度仍0。即使响应同时携带合法部分提案和未决问题，公共就绪门及工作台也不会应用部分修改。超出选中范围的操作被拒绝。

反例会将纠正后的50换回70、删掉标签里的否定词、增加排除的控件、合并同名行，独立期望均能检出。CLI替身测试确认三个运输路径都实际带上新提示，仍为单次调用、失败不自动重试。

这证明的是协议表达能力、就绪门与状态保护，**不是模型已理解24种输入**。尤其纠正、排除及开放式多项要求仍主要由Agent解释；该批使用的 `explicit-properties-v2` 对无法可靠识别的语句保持未核对，不会凭来源引用宣称语义正确。后续Studio已加入[0.13精确按钮文案核对](button-copy-checks.md)，同样保留通用语义未验收的边界。

新真实模型调用0次，历史授权均已消费。后续最有价值的真实复验候选是G01、G02、E05、E11：分别验证纠正、排除、同名点选和整批澄清。执行前仍需冻结具体上下文与摘要并取得新的单次授权；失败或结果不明即停止。未执行时状态保持NOT_RUN，不扩成一次大批调用。
