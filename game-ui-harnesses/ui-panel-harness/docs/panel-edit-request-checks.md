# 修改结果核对

Studio 的新修改上下文使用 EditContext 0.11。`requestChecks` 由程序从本轮
原文构建，绑定上下文摘要，不能由模型改写或删项。旧上下文保持原能力和摘要。
Draft 0.3、Proposal 0.1/0.2 与 PanelSpec/Bundle 格式保持原版本。

当前自动核对范围是完整、明确的中文几何短句，例如：

`改成9:16竖版，宽480，内边距24，标题区域高56，间距12。`

支持面板宽度、固定高度、比例、内边距、布局间距、标题区域高度、分组标题高度、
行高度和标签区域宽度。数字可带空格、像素或 px。只读取最终 Spec；要求原本已
满足时无需制造多余操作。遗漏、写错或以“无需修改”跳过不满足的值，均以
`EDIT_REQUEST_INCOMPLETE` 整轮拒绝；不会改面板、试玩值、历史或已用轮次。
需要澄清时仍保留原面板，不强迫模型猜测，也不自动再次调用。

这不是通用自然语言语义验收。相对调整、否定、引用文本、示例、改口、重复赋值、
回答记录与选中控件请求不做几何推断。它们仍交给 Agent 解释，不能据此宣称
全部要求已验证。`semanticReview` 始终为 `NOT_RUN`。

修改成功后，“上次实际变化”列出程序对比的前后值，并列出已经核对的几何
要求。新增或移除控件按稳定 ID 比较，避免插入一个控件误报后续所有控件被修改。
摘要仅对应会话中最近仍生效的事务；渲染失败不发布摘要，撤销会回到前一事务。
刷新或重新导入会清空会话历史及摘要，已用修改轮次沿用现有存档机制。

校验用例及浏览器演练使用程序编写的方案，不代表真实模型成功率；本次未调用模型。
