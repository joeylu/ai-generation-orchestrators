## 两类确定问题

S08、S16、S24、S32退出确认均使用非模态Dialog，状态初始为打开，只有内部取消和外部退出按钮。`modal:false`取消了模态限制，但浮动对话框仍覆盖外部按钮。离线浏览器从初始状态点击退出按钮的预期坐标，目标退出事件数均为0；其后关闭Dialog再测试外部按钮可以发事件。因此常规控件检查通过，不能掩盖初始确认流程不可操作。逻辑画布内未裁切也不等于没有相互覆盖。

S29“弄个选角色界面”实际产出了完整原生方案，规划回执为READY_TO_COMPILE，但交付编译失败。图片源为null、标签“角色立绘占位（示例）”、槽宽128高160，完整标签放不下，触发 `IMAGE_PLACEHOLDER_LABEL`。这是尺寸适配问题，并非未标明占位或缺少真实图片；没有把失败计为原始交付成功。

## 明确离线修正

- 4份退出：通过公开patch删除遮挡操作的Dialog及关联布尔状态，保留原退出提问和原退出动作；在同一面板中放提示文字、退出按钮和独立取消按钮。其他Spec字段、保留状态与资源保持。
- S29：从与原始回执摘要一致的已保存失败方案恢复，仅把图片槽width改为fill，保留标签、高度、其他控件、动作和创建默认值；重新生成有效包。此为离线恢复，不是新模型输出，不改写原FAIL。

程序逐项验证补丁前后允许的差异、包结构和ZIP清单每个文件的字节数／SHA-256。完成版为 `output/panel-stability-reviewed-patches-v3`。前两次修正程序在S29处分别因摘要字段读取、缺少显式assetLibrary:null而停止，部分输出v1／v2保留；一次浏览器预演因修正报告尚未完成而未启动，0项检查，失败日志保留，未消费任何模型授权。

5份完成版通过51项浏览器检查。4份退出与取消分别从重新加载的初始状态点击，两个动作都可达、事件正确，缺陷标记为0；S29占位文字通过编译尺寸检查，选择和确认可操作。修正只验证本地UI和宿主事件，真实游戏退出与认证服务未接入。

## 生成条件与后续规则

本轮固定gpt-6-luna/xhigh、mint-light@0.23.0、编译器0.34.0，不注入skill摘录，不提供用户美术或公共测试纹理库。冻结摘要 `56c0c71b17fdbf0919d4334eadef2834511b180fe369aec602279e565b4df5f0` 的授权已消费，不能再次运行。

先完成原始审计，再保存被修改的3份源码与批准时指纹。之后收紧实验提示：需要两个选择的确认用Text加两个普通Button，明确非模态Dialog也可能遮挡外部操作；未提供美术的占位槽默认填满宽度，除非用户明确固定宽度。已知问题观察器新增对初始浮动Dialog加外部动作的提示。这些改动发生在真实测试之后，尚未通过真实模型复验，不能将5份离线修正当成其生成效果证据。

本轮已足以定位下一步：先针对退出确认和角色占位适配复验，暂无证据需要继续扩大面板种类。日常Studio／SDK默认、既有发布和标签未切换。用途、文案、示例数据适合度与真实资源语义仍需人工审阅；本轮人工批准内容的记录为NOT_RECORDED。
