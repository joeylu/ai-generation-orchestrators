# 数据行按可用宽度排列

Studio／SDK新默认目录 `modern-readable-game-data-layout`，主题0.30.0／0.30.1、`game-readable-v4`、Compiler0.43。0.42及更早目录保留；旧保存包不会自动迁移。

本次解决[0.42真实复测](grouped-readable-ten-real-results-2026-10-15.md)中商店和通关结算的并排数据占宽。模型返回的 `wrap:none` 仍表示每段文字不换行，不代表标签和值必须并排。

- 已经采用正文／上下排列的行保留现有布局。其余单行数据使用同组最大标签宽度对齐，整组能放下时并排；有一项放不下时，全组标签和值上下排列。
- 只调整位置和行高，不改标签、正文、textLayouts、字号、行序、分组、初值、试玩状态或宿主事件。语义分组不根据中文标签猜测。
- 普通单列默认420，暂停菜单360；明确的面板／画布尺寸仍然优先。已有文字换行按原规则测量，message.text确认问句不受影响。
- 单段不换行文字自身过长时，自动尺寸可扩宽；固定宽度不够时明确报 `DATA_TEXT_FIT`。不会插入换行、截断文字或缩小字号。显式高度不足也保持拒绝。
- Pixi与Unity文档共享同一份编译后几何及完整原文；Unity导入工具仍为0.1.8，没有修改原生数据格式。原生Unity执行另行验收。

这轮使用刚完成的10份0.42真实结果生成明确离线变体，没有新模型调用、人工改文案或语义拆组。商店571→420、结算490→420，其余8份面板编译画面结构保持原样；原始包与ZIP继续保留。实际生产短口令提示只补充“单行文字可以上下排列”的说明，未注入外部skill。

源Spec回归夹具为 `tests/fixtures/readable-data-regressions-v1.json`，只含公开Spec、状态、目录和原始包摘要，不包含调用传输或授权记录。测试覆盖10份0.42精确重放、数据单行完整性、上下与并排布局、固定尺寸、超长值拒绝、混合换行正文、确认框和默认提示路径。
