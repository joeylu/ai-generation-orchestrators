## 真实输入形态

用户指出真实请求通常只有“帮我做一个设置面板”，此前完整字段清单不适合检验自动设计。本轮保持用户输入短小，不附加尺寸、主题、完整控件或默认值。

12条×3组＝最多36次。三组为严格精简提示、草稿优先提示、草稿优先提示加既有game-ui-design摘录。前两组检验补全政策的影响，后两组检验skill增益；不声称评测所有skill。固定模型gpt-6-luna/xhigh、主题modern-mint-light@0.21.0、Compiler 0.32.0和原生schema。各案例三组context摘要一致，按案例轮换起始组；每项一次，串行，无自动重试，传输不确定停止。

系统允许草稿组选择常规控件、预览默认值、布局与标题，保留用户明示的内容和排除项。推测内容仅为可修改建议；示例分数、奖励、玩家信息、实时进度须标明示例或占位。按钮只通知宿主，不宣称真实联网、支付、下载或游戏行为。影响核心用途或能力不支持时仍可澄清。短用户输入不等于删除系统协议或目录。字体、正文对齐和普通行间距仍不属于模型自由字段。

## 评价避免唯一答案

P01—P08没有预设应有几个开关、几个按钮或什么默认值，也不预设唯一面板布局。P09—P12仅对明确约束做硬检查：控件数量、类型、命名、明确默认值、原文信息以及可用操作。不同的未明确分组或展示标题可以通过；澄清必要性不由正则或固定答案认证。

准备时的reference仅是测试适配器的一种程序夹具，不是模型答案。冻结expectation.expectedSpec为null；reference不进入模型context或提示。离线测试验证多种不同设置草稿都能进入审阅、澄清问题也会保留，同时明确请求多出控件、改名、改默认值或内容会被拒绝。

每项区分直接草稿、澄清、技术/明确约束失败、未运行。现有报告status PASS仅表示协议与明确约束检查通过，通过含义单独写入report，绝不表示内容合理或澄清必要。draft-review记录原始需求、所有实际控件/默认值/只读内容及问题，并明确未指定内容是待审建议；审计重新计算并核对记录。实际面板还须通过浏览器检查，澄清没有面板时不冒称渲染通过。

内容适合程度、补全是否恰当、示例是否诚实、问题是否必要、视觉质量均为人工审阅项。不会由程序自动宣布某组优胜。一次样本不证明稳定性；暂不处理澄清续答或失败重试，这些需要后续独立计划。
