# 按用途排版

`examples/modern-adaptive.catalog.json` 的八个主题固定为 `0.4.0`，声明
`visualStyle:modern-v3`，使用编译器 `0.7.3`。PanelSpec 0.7 和模型方案协议不变。
旧目录、旧主题和旧编译器继续按原规则还原；导入旧文件不会自动改版。

程序逐分区读取控件类型，决定展示结构，不根据中文按钮名称推断业务。

| 分区内容 | 排版 |
|---|---|
| 输入、只读文字及按钮 | 表单：输入标签在上，末尾连续操作按钮组成底部按钮组 |
| 只读文字及按钮 | 对话框：内容在前，操作按钮在底部 |
| 全部是按钮 | 菜单：竖排、宽度一致 |
| 滑条、开关、下拉、进度或其他混合控件 | 设置列表：保持标签与控件的行结构，各行独立计高 |

表单及对话框的第一个提交操作采用主按钮；没有提交时，第一个通知宿主操作采用主按钮。
其余采用描边按钮。控件顺序、事件、提交范围与恢复默认范围保持原约定。
按钮组文案宽度不足时改为竖排，避免截断。新按钮高44逻辑像素。
输入框保留完整校验提示行，提示出现不推动布局。
滚动区域必须容纳一个完整的输入行，不能把校验提示永久切掉。

未指定尺寸的简单表单默认宽420逻辑像素，文案较长时程序增加宽度。
明确指定的宽、高和布局结构继续接受严格几何校验，不通过则报错。
仅当单分区表单或对话框的标题与面板标题相同（忽略末尾“界面”或“面板”）时，
不再重复绘制分区标题；原文仍保存于PanelSpec。
模型规划提示建议普通表单及确认/取消按钮不添加装饰图标；显式选定的资源仍会绘制。

```sh
node scripts/build-workbench.mjs --catalog examples/modern-adaptive.catalog.json --output output/my-adaptive-studio
node scripts/serve-workbench.mjs --workbench output/my-adaptive-studio --output-root output/my-adaptive-runs --port 0
node --test tests/panel-presentation.test.mjs
```

Studio对新面板按原始尺寸展示，窄屏缩小，不把小表单拉伸填满预览区。
原生输入代理具有可用文本宽度，连续中文输入不会把光标拉回开头；不改变可见控件样式。

本工作区的[用途排版预览](../output/panel-adaptive-review-v4/index.html)包含保存的角色命名结果、
明确的视觉派生、八主题表单和混合页签、长按钮、菜单、对话框、滚动表单及三种组合。
视觉派生只更换主题/几何并移除三个未要求的装饰图标；原始方案与模型回执保留。
其他样例为离线夹具，不计入真实模型生成成功率。Unity导出使用相同矩形与样式，
本次未运行Unity目标工程。

独立预览在页面根部保留滚动条占位，避免 iframe 高度临界时反复改变可用宽度。
尺寸通知合并到下一帧执行，避免观察器回调内写高度。容器只有有效缩放发生变化才更新画布；
高度通知、相同宽度及自然尺寸以上的宽度变化
不会重设绘图缓冲区或取消正在进行的手势。

尺寸循环的浏览器回归可独立运行，不调用模型：

```sh
node scripts/serve-viewport-check.mjs --output output/my-viewport-check
```

在浏览器打开命令打印的本地 URL，夹具自动检查16个宽度，将旧算法的循环与修复后的
真实 Pixi 绘制次数写入 `browser-report.json`。完成后终止该测试服务器。
